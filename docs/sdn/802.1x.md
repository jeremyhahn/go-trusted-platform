# 802.1X Port-Based Authentication

> **Status: REFERENCE** · Last verified: 2026-10-15
> Certificate-based port access control in the SDN policy engine.

## Overview

The SDN policy engine implements IEEE 802.1X-style port-based network access control
using certificate-based authentication. Instead of traditional EAP/RADIUS, devices
authenticate using IDevID certificates issued through ACME enrollment.

## Port State Machine

The policy engine manages port authentication through a state machine
(`pkg/sdn/policy/state.go`). The enrollment path is:

```
Unconnected ──SetPortState(provisioning)──▶ Provisioning      provisioning zone (VLAN x05)
                                                 │
                         OnEnrollmentComplete(event)
                                                 ▼
                                             Enrolled           still the provisioning zone,
                                                 │              awaiting client activation
                                ActivateDevice(plan)
                                                 ▼
                                            Authorized          the zones of the device
                                                                role's port class
```

`RegisterPort(mac, portID)` on the enrollment hook only records the
MAC-to-port mapping; the port enters provisioning through `SetPortState`.
A certificate that expires or is revoked **blocks** the port
(`OnCertificateExpired` / `OnCertificateRevoked`); nothing moves a port to
quarantined automatically. Leaving blocked takes an administrator:
`UnblockPort` removes the drop flows, brings the port up and returns it to
provisioning.

Every VLAN comes from the environment's network plan
([reference network](../architecture/reference-network.md)): quarantine is
VLAN x04 of the environment block (404 in environment 4), provisioning x05.

## Certificate-Based Policies

### Policy Extraction

The policy engine extracts network policies from X.509 certificates:

```go
// PolicyExtractor interface
type PolicyExtractor interface {
    ExtractPolicy(cert *x509.Certificate) (*PortPolicy, error)
    ExtractTenantID(cert *x509.Certificate) (string, error)
    ExtractZone(cert *x509.Certificate) (string, error)
    ExtractACLs(cert *x509.Certificate) ([]ACLRule, error)
}

// X509PolicyExtractor, the default:
// - TenantID: Subject.Organization[0], else the first label of the CN
// - Zone: the network-zone extension (1.3.6.1.4.1.29377.101.21), optional
// - ACLs: one allow-all rule (priority 100); no certificate extension is read
```

A zone the resolved zone set does not declare places the port in the
quarantine zone and returns `ErrZoneNotDeclared` (fail closed).

### Certificate Fields Used

| Field | Policy Attribute | Example |
|-------|------------------|---------|
| Subject.Organization (else CN) | Tenant ID | "Acme Corp" |
| NotAfter | Policy expiration (`ExpiresAt`) | 2026-01-01 |
| Network-zone extension | Zone | "hypervisor" |

### Policy Structure

```go
type PortPolicy struct {
    // TenantID from the certificate subject
    TenantID string

    // Zone, when set, is resolved to the VLAN through the zone plan
    Zone zone.Zone

    // VLAN, resolved from Zone or supplied directly when Zone is empty
    VLAN uint16

    // ACL rules
    ACLs []ACLRule

    // The authenticating certificate
    Certificate *x509.Certificate

    // Expiration time
    ExpiresAt time.Time

    // When the policy was issued
    IssuedAt time.Time

    // Metadata for logging/auditing
    Metadata map[string]string
}

type ACLRule struct {
    Priority    int
    Match       FlowMatch
    Action      FlowAction
    Description string
}
```

## Enrollment Integration

### SDN Enrollment Hook

The enrollment hook moves a fabric port to enrolled once its certificate is
issued:

```go
import "github.com/jeremyhahn/go-trusted-platform/pkg/sdn/policy"

// Create enrollment hook
config := policy.SDNEnrollmentHookConfig{
    Logger:       logger,
    PolicyEngine: policyEngine,
    ProfileDAO:   profileDAO,
}

hook, err := policy.NewSDNEnrollmentHook(config)
```

`SDNEnrollmentHookConfig` also takes `MACExtractor`, `PortBinder`,
`Extractor` and `Zones`. The device registry handler calls
`hook.OnEnrollmentComplete(event)` after a certificate is issued
(`pkg/webservice/v1/registry.go`).

### Enrollment Event

```go
type EnrollmentEvent struct {
    // Request context
    Context context.Context

    // Issued certificate
    Certificate *x509.Certificate

    // The same certificate, PEM-encoded
    CertificatePEM []byte

    // Client IP (for ARP lookup)
    ClientIP string

    // TCG-CSR-IDEVID specific fields
    IsTCGCSR      bool
    ProductModel  string
    ProductSerial string

    // Device permanent identifier
    PermanentIdentifier string
}
```

### Enrollment Flow

1. **Device connects** - Port registered in Provisioning state (provisioning zone, VLAN x05)
2. **ACME enrollment** - Device obtains IDevID certificate
3. **Hook triggered** - OnEnrollmentComplete called with certificate
4. **Profile lookup** - Find device profile by product serial, then by the MAC behind the client IP
5. **State transition** - Port moves to Enrolled state
6. **Client activation** - Device calls /api/v1/device/activate
7. **Policy applied** - Production VLAN and ACLs installed

Steps 1 and 5 require a fabric port. When enrollment happens before the
device attaches to the OVS fabric (e.g. over the management LAN), the hook
logs a WARN, records the pending activation with the device MAC, and returns
success; the state transition is deferred until the port exists, and
activation resolves the port from the MAC once a connect event has
registered it.

## State Transitions

### Valid Transitions

| From | To |
|------|----|
| Unconnected | Provisioning |
| Provisioning | Enrolled, Unauthorized, Authenticating, Authorized |
| Enrolled | Authorized, Provisioning |
| Unauthorized | Authenticating, Provisioning |
| Authenticating | Authorized, Unauthorized |
| Authorized | Unauthorized, Quarantined |
| Quarantined | Authorized, Provisioning |
| Blocked | Unconnected (admin reset), Provisioning (admin re-enrollment) |
| Any other state | Blocked |

`OnEnrollmentComplete` moves provisioning to enrolled, `ApplyPolicy` moves
the port through authenticating to authorized (enrolled may go straight to
authorized), and `BlockPort`, certificate expiry and certificate revocation
move any state to blocked.

### Transition Handlers

```go
// Set port state directly
err := engine.SetPortState("eth1", policy.PortStateProvisioning)

// Apply policy (transitions through authenticating to authorized)
err := engine.ApplyPolicy("eth1", portPolicy)

// Block port (installs DROP flows)
err := engine.BlockPort("eth1")

// Unblock port (removes DROP flows, returns to provisioning)
err := engine.UnblockPort("eth1")
```

### Port Management

### VLAN Management

```go
// Set port VLAN directly (OVSDB tag)

// Get port VLAN (from policy)

```

### Certificate Authentication

```go
// Authenticate port with certificate
err := engine.AuthenticatePort("eth1", certificate)

// Handle certificate expiry (blocks the port)
err := engine.OnCertificateExpired("eth1")

// Handle certificate revocation (blocks the port)
err := engine.OnCertificateRevoked("eth1")
```

## Flow Rules Generated

Rule priorities are offsets from a base priority of 1000
(`pkg/sdn/policy/rules.go`).

### Provisioning, Enrolled, Authenticating, Quarantined

`SetPortState` installs no flows for these states. What a provisioning port
reaches is set by the zone the port sits in, not by this engine.

### Authorized State

`ApplyPolicy` takes one of two paths:

- **Zone path** — the policy carries a zone and a `ZoneFlowManager` is
  configured. `ApplyZoneFlows` resolves the zone's VLAN, sets it as the
  port's access VLAN through OVSDB (clearing any trunk), replaces the port's
  flows with the per-zone template flows and appends the inter-zone matrix
  rules. A quarantine-zone policy is refused when no `ZoneFlowManager` is
  configured.
- **VLAN path** — no zone, `VLAN` set. The VLAN is set through OVSDB, then:

```
# VLAN tag
priority=1100,in_port=<port>,actions=mod_vlan_vid:<vlan>,<terminal>

# One rule per ACL, at 1000 + the ACL's priority
priority=1100,in_port=<port>,dl_vlan=<vlan>,...,actions=normal

# Only when the policy has no ACLs: default allow
priority=1000,in_port=<port>,dl_vlan=<vlan>,actions=<terminal>
```

`<terminal>` is the engine's configured terminal action (`Config.Terminal`).
No default-drop rule is installed.

### Unauthorized State

```
priority=1500,in_port=<port>,actions=drop
```

### Blocked State

```
# High priority drop for all traffic
priority=2000,in_port=<port>,actions=drop

# Additionally, OVSDB sets the port admin state down
```

## Certificate Monitoring

### Enable Monitoring

```go
config := policy.Config{
    BridgeName:       "br0",
    FlowController:   flowController, // must also implement OVSPortController, or set PortController
    EnableMonitoring: true,
    MonitorConfig: policy.MonitorConfig{
        CheckInterval:   time.Hour,
        ExpiryThreshold: 7 * 24 * time.Hour, // 7 days
    },
}

engine, err := policy.NewEngine(config)

// Get monitor for callbacks
monitor := engine.GetMonitor()
if err := monitor.Start(ctx); err != nil {
    return err
}
defer monitor.Stop()
```

### Expiry Handling

Every `CheckInterval` the monitor checks each port's certificate:
1. Expiring within `ExpiryThreshold` - the registered callbacks are notified; the port is unchanged
2. Expired - `OnCertificateExpired` removes the port's flows and blocks it

## Integration with Compute

The compute orchestrator integrates with SDN policy for VM network access:

```go
// Configure orchestrator with policy engine
config := &compute.OrchestratorConfig{
    PortAuthEnabled: true,
    PolicyEngine:    policyEngine,
}

orchestrator, err := compute.NewQEMUOrchestrator(config, logger)

// When VM network is attached, port enters provisioning
err = orchestrator.AttachNetwork(ctx, instanceID, "eth0")

// After enrollment, activate the instance
err = orchestrator.ActivateInstance(ctx, instanceID, productionPolicy)
```

See [802.1X Network Attachment](../compute/802.1X-network-attachment.md) for details.

## Security Considerations

1. **Certificate Validation** - `AuthenticatePort` validates the certificate with the configured `CertificateValidator` before extracting a policy
2. **Revocation Checking** - `DefaultCertificateValidator` checks an in-memory revocation list (`AddRevoked` / `RemoveRevoked`); there is no CRL or OCSP check
3. **Expiry Enforcement** - The monitor blocks the port of an expired certificate
4. **Zone Isolation** - Provisioning and quarantine are separate zones; an undeclared certificate zone falls back to quarantine
5. **Defense in Depth** - Both an OpenFlow drop and the OVSDB admin state for blocking
6. **Audit Logging** - State transitions are logged
7. **Attempt Counting** - `AuthAttempts` is counted per port; no limit is enforced

## Troubleshooting

### Port Stuck in Provisioning

```bash
# Check port state
platformctl sdn port state eth1 --bridge br0

# Verify enrollment completed
journalctl -u platformd | grep -e "processing enrollment completion" -e "awaiting activation"

# Check ARP table for MAC
cat /proc/net/arp | grep <ip>
```

### Certificate Not Accepted

```bash
# Verify certificate validity
openssl x509 -in cert.pem -noout -dates

# Check certificate chain
openssl verify -CAfile ca.pem cert.pem

# View certificate details
openssl x509 -in cert.pem -noout -text
```

### Flows Not Applied

```bash
# Check OpenFlow flows
ovs-ofctl dump-flows br0 | grep <port>

# Verify port VLAN
ovs-vsctl get port eth1 tag

# Check bridge configuration
ovs-vsctl show
```
