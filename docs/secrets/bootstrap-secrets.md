This document describes secret resolution and migration during platform bootstrap.

## Overview

During platform bootstrap, secrets referenced in configuration using special URI schemes are resolved to their plaintext values and migrated to the local KMS for unified access.

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  Config File    │     │  Secret Manager │     │   Local KMS     │
│  (URI refs)     │────>│   (Resolvers)   │────>│   (QuicBaaS)    │
└─────────────────┘     └─────────────────┘     └─────────────────┘
        │                       │                       │
        ▼                       ▼                       ▼
  idevid://...        Decrypt/Fetch/Gen        kms://config/...
  remote-kms://...       Plaintext value          Unified access
  autogen://...          Store in KMS             Config updated
```

## URI Schemes

| Scheme | Description | Resolver |
|--------|-------------|----------|
| `kms://` | Local QuicBaaS KMS | LocalKMSResolver |
| `remote-kms://` | Remote KMS via mTLS | RemoteKMSResolver |
| `idevid://` | RSA-OAEP encrypted to IDevID | IDevIDResolver |
| `autogen://` | Generate random secret | AutoGenResolver |
| `env://` | Environment variable | EnvResolver |

## Migration Process

### 1. Configuration Scanning

The SecretManager walks the configuration struct using reflection:

```go
manager, err := bootstrap.NewSecretManager(registry, kms, "config", logger)
result, err := manager.ProcessConfig(ctx, appConfig)
```

String fields containing URI prefixes are identified for resolution.

### 2. Secret Resolution

Each URI is routed to the appropriate resolver:

```go
// Registry routes URIs to resolvers
secretValue, err := registry.Resolve(ctx, "idevid://SGVsbG8...")
```

Resolvers handle scheme-specific logic:
- `IDevIDResolver`: TPM decrypt via IDevID
- `LocalKMSResolver`: QuicBaaS lookup
- `AutoGenResolver`: crypto/rand generation

### 3. KMS Storage

Resolved secrets are stored in local KMS:

```go
kmsPath := "config/kms/backends/tpm2/srk-auth"
err := kms.StoreSecret(ctx, kmsPath, plaintext, metadata)
```

Secrets are stored as AES-256 symmetric keys with metadata tracking the original source.

### 4. Config Update

Optionally, the config file is updated with `kms://` references:

```yaml
# Before
kms:
  backends:
    tpm2:
      srk-auth: "idevid://SGVsbG8..."

# After
kms:
  backends:
    tpm2:
      srk-auth: "kms://config/kms/backends/tpm2/srk-auth"
```

## Configuration

```yaml
secrets:
  # Enable secret resolution during bootstrap
  enabled: true

  # Enable autogen:// resolver
  auto-generate: true

  # Enable kms:// resolver (local KMS)
  local-kms: true

  # Enable remote-kms:// resolver
  remote-kms: false

  # Enable idevid:// resolver (requires IDevID)
  encrypted: true

  # Migrate resolved secrets to local KMS
  migrate-to-kms: true

  # Update config file with kms:// references
  update-config-file: false
```

## MigrationResult

Processing returns a MigrationResult with details:

```go
type MigrationResult struct {
    // Secrets resolved and stored in KMS
    Migrated []MigratedSecret

    // Config paths of auto-generated secrets
    AutoGenerated []string

    // Non-fatal errors encountered
    Errors []error
}

type MigratedSecret struct {
    ConfigPath  string  // "kms.backends.tpm2.srk-auth"
    KMSPath     string  // "kms://config/kms/backends/tpm2/srk-auth"
    Strategy    string  // "idevid", "remote-kms", "autogen"
    OriginalURI string  // Masked URI for logging
}
```

## Security Considerations

### Memory Handling

- Plaintext secrets cleared from memory after KMS storage
- `SecretValue.Clear()` zeros the value slice
- Avoid logging plaintext values

### Config Backup

When updating config files, a backup is created first:

```go
backupPath, err := writer.Backup()
// Creates: /etc/trusted-platform/node.yaml.bak.20260111150000
```

On failure, the original config is restored.

### Error Handling

Non-fatal errors are collected without stopping migration:

```go
if result.HasErrors() {
    for _, err := range result.Errors {
        logger.Warn("migration error", "error", err)
    }
}
```

Fatal errors (nil config, nil registry) stop processing immediately.

## CLI Commands

The `platformctl bootstrap secrets` command group provides secret management:

### Migrate Secrets

```bash
# Migrate all secrets to local KMS
platformctl bootstrap secrets migrate --config /etc/trusted-platform/config.yaml

# Preview changes without modifying files
platformctl bootstrap secrets migrate --config /etc/trusted-platform/config.yaml --dry-run

# Skip backup creation
platformctl bootstrap secrets migrate --config /etc/trusted-platform/config.yaml --no-backup
```

### Check Status

```bash
# Show secret resolution status
platformctl bootstrap secrets status --config /etc/trusted-platform/config.yaml

# Show masked URIs
platformctl bootstrap secrets status --config /etc/trusted-platform/config.yaml --show-uris
```

### Verify Secrets

```bash
# Verify all secrets can be resolved
platformctl bootstrap secrets verify --config /etc/trusted-platform/config.yaml

# Check resolver availability without resolving
platformctl bootstrap secrets verify --config /etc/trusted-platform/config.yaml --dry-run

# Stop on first failure
platformctl bootstrap secrets verify --config /etc/trusted-platform/config.yaml --fail-fast
```

### Resolve Single Secret

```bash
# Resolve and display masked value
platformctl bootstrap secrets resolve "kms://config/db/password"

# Show full value (for debugging)
platformctl bootstrap secrets resolve "kms://config/db/password" --raw
```
