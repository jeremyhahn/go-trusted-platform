The secrets framework provides secure resolution and migration of secrets in go-trusted-platform. It enables configuration values to reference secrets from multiple sources using URI schemes, automatically resolving them at runtime and optionally migrating them to a unified local KMS for consistent access.

## Overview

Secrets in configuration files are represented as URIs with specific schemes (e.g., `kms://`, `idevid://`). During platform bootstrap, the secrets framework:

1. Scans configuration structs for secret URIs
2. Routes each URI to the appropriate resolver
3. Resolves secrets to plaintext values
4. Migrates resolved secrets to local KMS (optional)
5. Updates configuration files with `kms://` references (optional)

```
Configuration              Resolution                  Storage
+------------------+      +------------------+      +------------------+
|  idevid://... | ---> | IDevIDResolver| ---> |                  |
|  remote-kms://...|      | RemoteKMSResolver|      |   Local KMS      |
|  autogen://...   | ---> | AutoGenResolver  | ---> |   (QuicBaaS)     |
|  kms://...       |      | LocalKMSResolver |      |                  |
+------------------+      +------------------+      +------------------+
                                 |                         |
                                 v                         v
                          Plaintext Value           kms://config/...
```

## Architecture

The secrets framework spans two repositories with distinct responsibilities:

### go-quicbaas (Core Framework)

Location: `pkg/config/secrets`

Provides the foundational resolution infrastructure:

- `SecretResolver` interface for implementing resolvers
- `ResolverRegistry` for managing multiple resolvers
- `SecretManager` for orchestrating resolution and migration
- `ConfigWriter` for atomic configuration updates
- Core resolvers: `LocalKMSResolver`, `RemoteKMSResolver`, `AutoGenResolver`

### go-trusted-platform (Platform Extensions)

Location: `pkg/config/secrets`, `pkg/bootstrap`, `pkg/app`

Extends the core framework with platform-specific capabilities:

- `IDevIDResolver` for TPM-backed IDevID decryption
- Bootstrap integration for platform initialization
- CLI commands for secret management
- Integration with platform XKMS and TPM

## Quick Start

### Basic Configuration

Enable secret resolution in your platform configuration:

```yaml
secrets:
  enabled: true
  auto-generate: true
  local-kms: true
  encrypted: true
  migrate-to-kms: true
  update-config-file: false
```

### Using Secret URIs

Reference secrets in configuration using URI schemes:

```yaml
database:
  # Auto-generate a random password on first boot
  password: "autogen://32/base64"

kms:
  backends:
    tpm2:
      # Encrypted to node's IDevID certificate
      srk-auth: "idevid://SGVsbG8gV29ybGQhIFRoaXMgaXMgYW4gZW5jcnlwdGVkIHNlY3JldA=="

      # Fetch from remote KMS via mTLS
      owner-auth: "remote-kms://secrets/node-001/owner-auth"
```

### Programmatic Usage

```go
// Setup resolver registry
logger := slog.New(slog.NewJSONHandler(os.Stdout, nil))
registry := bootstrap.NewResolverRegistry(logger)

// Register resolvers
registry.Register(NewAutoGenResolver(logger))
registry.Register(NewLocalKMSResolver(kms, logger))
registry.Register(secrets.NewIDevIDResolver(decrypter, logger))

// Create secret manager
manager, err := bootstrap.NewSecretManager(registry, kmsClient, "config", logger)
if err != nil {
    return err
}

// Process configuration
result, err := manager.ProcessConfig(ctx, appConfig)
if err != nil {
    return err
}

// Check results
fmt.Printf("Migrated: %d, Auto-generated: %d, Errors: %d\n",
    result.MigratedCount(),
    result.AutoGeneratedCount(),
    result.ErrorCount())
```

## Components

### ResolverRegistry

Manages multiple secret resolvers and routes resolution requests based on URI scheme.

```go
type ResolverRegistry struct {
    resolvers map[string]SecretResolver
    logger    *slog.Logger
}

// Register a resolver
registry.Register(resolver)

// Resolve a URI (automatically routes to correct resolver)
value, err := registry.Resolve(ctx, "idevid://...")

// Check if any resolver can handle a URI
canResolve := registry.CanResolve("kms://path")
```

### SecretResolver Interface

All resolvers implement this interface:

```go
type SecretResolver interface {
    // Scheme returns the URI scheme (e.g., "idevid")
    Scheme() string

    // CanResolve returns true if this resolver handles the URI
    CanResolve(uri string) bool

    // Resolve decrypts or retrieves the secret value
    Resolve(ctx context.Context, uri string) ([]byte, error)
}
```

### SecretManager

Orchestrates secret resolution and migration during bootstrap.

```go
type SecretManager struct {
    registry   *ResolverRegistry
    localKMS   SecretsClient
    configPath string
    logger     *slog.Logger
}

// Create manager
manager, err := NewSecretManager(registry, kmsClient, "config", logger)

// Process config struct (walks all fields via reflection)
result, err := manager.ProcessConfig(ctx, configStruct)
```

The manager uses reflection to walk configuration structs, identifying string fields with secret URI prefixes and resolving them automatically.

### ConfigWriter

Handles atomic configuration file updates with backup support.

```go
// Create writer
writer, err := bootstrap.NewConfigWriter("/etc/trusted-platform/config.yaml", logger)

// Create backup before changes
backupPath, err := writer.Backup()

// Apply secret reference updates
updates := []bootstrap.SecretUpdate{
    {
        Path:          "kms.backends.tpm2.srk-auth",
        KMSReference:  "kms://config/kms/backends/tpm2/srk-auth",
        OriginalValue: "idevid://...",
    },
}
err = writer.UpdateSecretReferences(updates)

// Restore from backup on failure
err = writer.Restore(backupPath)
```

### MigrationResult

Contains results from processing secrets:

```go
type MigrationResult struct {
    // Successfully migrated secrets
    Migrated []MigratedSecret

    // Paths of auto-generated secrets
    AutoGenerated []string

    // Non-fatal errors encountered
    Errors []error
}

// Helper methods
result.MigratedCount()      // Count of migrated secrets
result.AutoGeneratedCount() // Count of auto-generated secrets
result.HasErrors()          // True if any errors occurred
result.ErrorCount()         // Number of errors
```

## Supported Resolvers

| Resolver | Scheme | Package | Description |
|----------|--------|---------|-------------|
| LocalKMSResolver | `kms://` | go-quicbaas | Retrieves secrets from local QuicBaaS KMS |
| RemoteKMSResolver | `remote-kms://` | go-quicbaas | Fetches secrets from remote KMS via mTLS |
| AutoGenResolver | `autogen://` | go-quicbaas | Generates random secrets with crypto/rand |
| EnvResolver | `env://` | go-quicbaas | Reads secrets from environment variables |
| IDevIDResolver | `idevid://` | go-trusted-platform | Decrypts RSA-OAEP encrypted secrets via IDevID |
| FileResolver | `file://` | go-trusted-platform | Reads raw secret bytes from a local file (airgap/dev escape hatch, opt-in) |

### URI Format Examples

```yaml
# Local KMS - retrieve existing secret
password: "kms://config/database/password"

# Remote KMS - fetch from provisioning server
srk-auth: "remote-kms://secrets/node-001/srk-auth"

# Auto-generate - create random secret
api-key: "autogen://32/base64"     # 32 bytes, base64 encoded
pin: "autogen://16/hex"            # 16 bytes, hex encoded
token: "autogen://64"              # 64 raw bytes

# Environment variable
db-password: "env://DATABASE_PASSWORD"

# Encrypted - RSA-OAEP to IDevID certificate
owner-auth: "idevid://SGVsbG8gV29ybGQh..."
```

## CLI Commands

The `platformctl bootstrap secrets` command group provides management operations:

### migrate

Migrate plaintext or external secrets to local KMS:

```bash
# Migrate with backup (recommended)
platformctl bootstrap secrets migrate --config /etc/trusted-platform/config.yaml

# Preview changes without modifying files
platformctl bootstrap secrets migrate --config /etc/trusted-platform/config.yaml --dry-run

# Migrate without creating backup
platformctl bootstrap secrets migrate --config /etc/trusted-platform/config.yaml --no-backup

# Continue migration even if some secrets fail
platformctl bootstrap secrets migrate --config /etc/trusted-platform/config.yaml --force
```

### status

Display secret resolution status for a configuration file:

```bash
# Show summary
platformctl bootstrap secrets status --config /etc/trusted-platform/config.yaml

# Show with masked URIs
platformctl bootstrap secrets status --config /etc/trusted-platform/config.yaml --show-uris
```

Output includes:
- Total secrets by scheme
- Resolver availability
- Migration recommendations

### verify

Verify all secrets in configuration can be resolved:

```bash
# Verify all secrets
platformctl bootstrap secrets verify --config /etc/trusted-platform/config.yaml

# Check resolver availability only (no resolution)
platformctl bootstrap secrets verify --config /etc/trusted-platform/config.yaml --dry-run

# Stop on first failure
platformctl bootstrap secrets verify --config /etc/trusted-platform/config.yaml --fail-fast

# Show resolved values (debugging only)
platformctl bootstrap secrets verify --config /etc/trusted-platform/config.yaml --show-secrets
```

### resolve

Resolve a single secret URI for testing:

```bash
# Resolve with masked output (default)
platformctl bootstrap secrets resolve "kms://config/db/password"

# Show full resolved value
platformctl bootstrap secrets resolve "kms://config/db/password" --raw

# Test auto-generation
platformctl bootstrap secrets resolve "autogen://32/base64"
```

## Configuration Options

Full secrets configuration in `platform.yaml`:

```yaml
secrets:
  # Enable secret resolution during bootstrap
  enabled: true

  # Enable autogen:// resolver for random generation
  auto-generate: true

  # Enable kms:// resolver for local KMS access
  local-kms: true

  # Enable remote-kms:// resolver for remote KMS via mTLS
  remote-kms: false

  # Enable idevid:// resolver (requires IDevID)
  encrypted: true

  # Enable file:// resolver (airgap/dev escape hatch; reads plaintext
  # secret bytes from local files — never enable where a KMS is reachable)
  file: false

  # Store resolved secrets in local KMS
  migrate-to-kms: true

  # Update config file with kms:// URIs after migration
  # WARNING: Modifies configuration file
  update-config-file: false
```

## Security Considerations

### Memory Handling

- Plaintext secrets are cleared from memory after KMS storage
- Use `SecretValue.Clear()` to zero secret buffers
- Avoid logging plaintext values; URIs are masked in logs

### TPM-Backed Decryption

The `IDevIDResolver` uses RSA-OAEP with SHA-256 via the TPM:
- IDevID private key never leaves the TPM
- Decryption operations execute inside TPM hardware
- Key is bound to specific TPM chip (FixedTPM attribute)

### Atomic File Updates

Configuration file updates use atomic operations:
1. Write to temporary file in same directory
2. Sync to disk
3. Atomic rename to target path
4. Automatic backup before modifications

### Error Handling

Non-fatal errors are collected without stopping migration:

```go
if result.HasErrors() {
    for _, err := range result.Errors {
        logger.Warn("migration error", "error", err)
    }
}
```

Fatal errors (nil config, nil registry) stop processing immediately.
