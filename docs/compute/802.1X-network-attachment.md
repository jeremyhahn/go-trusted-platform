# 802.1X Network Attachment for VMs

> **Status: REFERENCE** · Last verified: 2026-10-13
> Deep dive on 802.1X port authentication for compute workloads and the SDN enrollment hook.

## Overview

The compute orchestrator integrates with the SDN policy engine to provide 802.1X-style
port-based network access control for virtual machines. When enabled, VMs start with
restricted network access (provisioning state) and must complete enrollment before
gaining full production network access.

## Port States

| State | Description | Network Access |
|-------|-------------|----------------|
| Unconnected | Port not registered | None |
| Provisioning | VM attached, awaiting enrollment | Limited (DHCP, DNS, enrollment) |
| Enrolled | Enrollment complete, awaiting activation | Limited |
| Authorized | Full production access | Full (per policy ACLs) |
| Quarantined | Compliance issue | Isolated VLAN |
| Blocked | Certificate revoked | None (DROP all) |

## Configuration

### Enable Port Authentication

```go
config := &compute.OrchestratorConfig{
    Type:            compute.ComputeTypeVM,
    WorkDir:         "/var/lib/trusted-platform/vms",
    MaxInstances:    100,

    // Enable 802.1X port authentication
    PortAuthEnabled: true,
    PolicyEngine:    policyEngine,  // From pkg/sdn/policy
}

orchestrator, err := compute.NewQEMUOrchestrator(config, logger)
```

### Disable Port Authentication (Default)

```go
config := &compute.OrchestratorConfig{
    Type:         compute.ComputeTypeVM,
    WorkDir:      "/var/lib/trusted-platform/vms",
    // PortAuthEnabled defaults to false
    // PolicyEngine defaults to nil
}
```

## API

### AttachNetwork

Attaches a network interface to a VM instance.

```go
err := orchestrator.AttachNetwork(ctx, instanceID, "eth0")
```

When `PortAuthEnabled` is true:
1. Creates TAP device and OVS port
2. Sets port to `PortStateProvisioning`
3. Installs limited access flows (DHCP, DNS, enrollment traffic)
4. Tracks instance-to-port mapping

When `PortAuthEnabled` is false:
1. Creates TAP device and OVS port
2. Full network access immediately

### ActivateInstance

Transitions a VM's network port from enrolled to authorized state.

```go
policy := &policy.PortPolicy{
    TenantID:  "tenant-1",
    VLAN:      100,
    ACLs: []policy.ACLRule{
        {
            Priority: 1000,
            Match:    policy.FlowMatch{IPProto: 6, TCPDst: 443},
            Action:   policy.FlowAction{Type: policy.FlowActionAllow},
        },
    },
    ExpiresAt: time.Now().Add(24 * time.Hour),
}

err := orchestrator.ActivateInstance(ctx, instanceID, policy)
```

This:
1. Looks up the port associated with the instance
2. Applies the policy via the policy engine
3. Sets port state to `PortStateAuthorized`
4. Installs production VLAN and ACL flows

### DetachNetwork

Detaches a network interface and cleans up port authentication.

```go
err := orchestrator.DetachNetwork(ctx, instanceID, "eth0")
```

When `PortAuthEnabled` is true:
1. Removes port from policy engine
2. Cleans up flows
3. Removes TAP device and OVS port
4. Removes instance-to-port mapping

## Workflow Example

### Complete Enrollment Flow

```go
// 1. Create VM instance
instance, err := orchestrator.Create(ctx, deviceProfile)

// 2. Attach network (port enters provisioning state)
err = orchestrator.AttachNetwork(ctx, instance.ID, "eth0")

// 3. Start VM (VM boots in provisioning network)
err = orchestrator.Start(ctx, instance.ID)

// 4. VM enrolls via ACME (handled by enrollment hook)
// - VM obtains IDevID certificate
// - Enrollment hook marks port as "enrolled"

// 5. VM activates (transition to production)
err = orchestrator.ActivateInstance(ctx, instance.ID, productionPolicy)

// 6. VM now has full production network access
```

### Integration with Enrollment Hook

The enrollment hook handles the enrollment-to-activation flow:

```go
// Configure enrollment hook
hook, err := policy.NewSDNEnrollmentHook(policy.SDNEnrollmentHookConfig{
    PolicyEngine: policyEngine,
    ProfileDAO:   deviceProfileDAO,
    // MACExtractor defaults to ARP-based extraction
})

// When device enrolls (ACME certificate issued):
err = hook.OnEnrollmentComplete(event) // *policy.EnrollmentEvent

// When device activates (POST /api/v1/device/activate):
result, err := hook.ActivateDevice(plan) // policy.ActivationPlan
```

## Port Authentication Helper Functions

### SetProvisioningState

Low-level function to set a port to provisioning state:

```go
config := &compute.PortAuthConfig{
    PortID:       "port-1",
    BridgeName:   "br0",
    PolicyEngine: policyEngine,
}

err := compute.SetProvisioningState(config)
```

### ActivatePort

Low-level function to activate a port with a policy:

```go
err := compute.ActivatePort(config, portPolicy)
```

### GetPortState

Retrieve current port authentication state:

```go
state, err := compute.GetPortState(config)
// state is one of: PortStateUnconnected, PortStateProvisioning, etc.
```

### RemovePortAuth

Remove port from authentication system:

```go
err := compute.RemovePortAuth(config)
```

## Error Handling

The helpers return `*compute.MessageError` for a missing config, port ID or
policy engine, and `*compute.WrappedError` around a policy engine failure.
A port the engine does not know surfaces as `policy.ErrPortNotFound`.

## Security Considerations

1. **Provisioning Network Isolation**: VMs in provisioning state can only reach:
   - DHCP (UDP 67, 68)
   - DNS (UDP/TCP 53, 8053)
   - Platform server (HTTPS 443, 8443)

2. **Certificate-Based Activation**: Production network access requires:
   - Valid IDevID certificate from CA
   - Device profile matching

3. **Automatic Cleanup**: When VMs are stopped or deleted:
   - Port state is cleared
   - Flows are removed
   - Instance-to-port mappings are deleted

4. **Thread Safety**: All operations are protected by mutex for concurrent access.
