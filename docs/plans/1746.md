# Plan: #1746 gateway BGP peers, prefixes and IPAM allocations in the web UI

Slice 14 of the UI epic #1665.

## Objective

Every gateway BGP and IPAM REST operation is reachable from a dashboard page
and exercised by a Playwright e2e test with mocked API responses:

- ListBGPPeers (`GET /bgp/peers`)
- AnnouncePrefix (`POST /bgp/prefixes`)
- WithdrawPrefix (`DELETE /bgp/prefixes`)
- AllocateIP (`POST /ipam/allocations`)
- ReleaseIP (`DELETE /ipam/allocations`)
- ListAllocations (`GET /allocations`)

## Slices in order

1. `web/e2e/gateway-bgp.spec.ts`: one `test.describe`, a `test.fixme` per
   operation (test first, ruling 286).
2. `web/src/hooks/use-gateway-bgp.ts`: fetch helpers for the six routes.
   `web/src/app/(dashboard)/networking/gateway/bgp/page.tsx`: peers table,
   announce form, withdraw (confirm dialog), allocate form, allocations
   table with release (confirm dialog). Nav entry beside the gateway page.
   The spec's `fixme` cases become real tests that mock each route.

The JS SDK `GatewayService` already carries all six methods with tests, so
the SDK is not changed.

3. Codex round 2 (#1759): the hook's loads carry a generation, so only the
   newest load sets state (mount fetch vs mutation refetch, overlapping
   refreshes). `use-gateway-bgp.race.test.tsx` covers out-of-order
   completion with deferred responses.

## Out of scope

Moving the hook onto the shared SDK client (Codex round 2 P2): it needs the
SDK `GatewayService` route fixes, outside this lane's file map.

Gateway mode, snapshots and admitted VTEPs (no REST route). No Go change.
