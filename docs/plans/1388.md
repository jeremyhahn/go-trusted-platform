# Plan: #1388 test-suite audit (ruling 273)

## Objective

Each behaviour is tested by one path at the uppermost layer that reaches it;
low-value tests (duplicates, tautologies, standard-library or dependency
tests, sleeps standing in for synchronisation) are removed. No behaviour
loses its only test, and the handbook coverage gate stays met.

## Slices (one package per slice, in order)

Earlier slices landed through trains #1394, #1874 and #1877 (struct and
constant read-backs, the `pkg/secureboot` keychain error-path duplicates).

1. `pkg/secureboot` (this lane), the duplicates left after #1394:

     `createXKMSBackend` with a keys dir under a regular file, the same path
     `TestGenerateAllMkdirError` takes through the public `NewXKMSManager`.
     That test now also asserts the "failed to create" error text.

2. Further packages, one slice per lane, each naming its surviving test for
