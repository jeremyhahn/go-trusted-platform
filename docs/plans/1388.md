# Plan: #1388 test-suite audit (ruling 273)

## Objective

Each behaviour is tested by one path at the uppermost layer that reaches it;
low-value tests (duplicates, tautologies, standard-library or dependency
tests, sleeps standing in for synchronisation) are removed. No behaviour
loses its only test, and the handbook coverage gate stays met.

constant read-backs, the `pkg/secureboot` keychain error-path duplicates).
