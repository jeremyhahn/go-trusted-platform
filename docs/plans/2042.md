# Plan: #2042 CeremonyService in the web UI (epic #1665, ruling 972)

## Objective

The web UI drives the seven CeremonyService operations (Init, Status,
ClaimCertBegin, ClaimCertComplete, ClaimShareBegin, ClaimShareComplete,
SignCSR) through the JavaScript SDK, every control capability-gated, and the
coverage matrix rows 109-115 read `covered`.

The web SDK is REST, and the webservice (/api/v1) had no ceremony route: the
daemon REST serves /ceremony/* on the daemon listener only. So the server
route comes first.

## Slices

1. Server route and SDK client (this slice).
   - pkg/webservice/v1/rest/ceremony: `POST /init`, `GET /status`,
     `POST /claim-cert/begin`, `POST /claim-cert/complete`,
     `POST /claim-share/begin`, `POST /claim-share/complete`,
     `POST /sign-csr`, over the in-process `CeremonyServiceServer`; admin
     gate, per-route ceremony scopes (pkg/api/iam/method_permissions.go),
     `Cache-Control: no-store` on every answer (Init returns the admin
     private key, ClaimShareComplete a Shamir share).
   - Wiring: registry, router, serve.go; routes.golden.
   - SDK `CeremonyService` as `client.ceremony`.
   - Tests: `TestCeremonyRouterServesEveryOperation`,
     `TestCeremonyRouterMapsServiceRefusals`,
     `TestCeremonyRouterWithoutAServiceIsUnavailable`,
     `TestCeremonyRouterRefusesBadBodies`, `TestCeremonyRouterSetsNoStore`,
     `TestCeremonyRouterRequiresEachRouteScope`; the router golden and
     gated-route tests; vitest ceremony-service.test.ts.
   - Matrix rows 109-115 get their REST column; status stays `missing`.
2. Page and hook.
   - `useCeremony()` on `client.ceremony` with a vitest.
   - Page: status card, Init form, claim-cert and claim-share flows, Sign
     CSR form, each control in `<Gated op="POST /api/v1/ceremony/...">`
     (capabilities row #2058).
   - Page vitest; test/integration/web/ceremony.spec.ts (no page.route).
   - Matrix rows 109-115 and the summary row to `covered`.

## Out of scope

- Any change to the daemon REST, the gRPC service or the ceremony logic
  under pkg/api/.
- A `make web-e2e` target and a real-server Playwright run (the harness
  auth fixture sets a mock JWT).
