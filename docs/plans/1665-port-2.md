# Epic #1665, #2036 part 2: port the mocked specs to the real-server harness

## Objective
Port this part's mocked Playwright specs to `web/e2e/real-server/`, seeded
through the SDK (`sdk`, `tenant`, `adminPage` from `./fixtures`) and asserting
on server answers. Each mocked original is deleted in the commit that adds
its port. Parts 1 (#2035) and 3 (#2037) keep their own plan files.

## Slices (in order)
1. Done: kms, networking, ntp, overlay, platform, provisioning, registry,
   storage. kms, ntp, overlay and registry are named `<name>-port.spec.ts`
   because other UI rows add specs of the same name.
2. New: iam-groups-tenants, iam-policies, iam, idevid (`idevid-port`),
   invitation-accept-flow, invitation-accept, invitations, kms-ops.

## Gaps for the route audit (part 2)
Mocked cases with no server behaviour behind them, dropped from the ports:
- kms: artificial list latency (loading spinner); injected 500 on list,
  detail, rotate and delete; injected 400 on delete; tenant-member session
  (harness seeds only the admin); the skipped encryption-operations block.
- networking: loading latency; injected 500s on VLAN, gateway, DNS, overlay
  and PXE reads; a 409 from a create-VLAN dialog that does not exist;
  hand-set port and flow counters and UP/DOWN ports; synthetic 503 role
  variants (only the harness node's real role is testable); member session;
  reported-gateway fleet telemetry.
- ntp: a status read held open; a refresh failing on cue (stale mark); a 409
  from Step; a confirmed Step (it would step the runner's clock).
- overlay: 403 denials on delete, forget MAC and the VTEP, tunnel and MAC
  lists; learned remote MACs; tunnel counters and a second node's VTEP.
- platform: unhealthy services on cue; 503 on health, metrics and events;
  latency; member session; the skipped logs and configuration placeholders.
- provisioning: pending and expired sessions; the SDK and API have no call
  that opens a session without a device enrolling, so the list is held to
  whatever the server holds and skips when empty.
- registry: tag list, delete-after-confirm and cancel; the SDK cannot push an
  image and the harness seeds none; the injected 500 status error.
- storage: key-value, vector, time-series and backup CRUD flows (page load
  only); injected 500 on list buckets; member session.
- iam-groups-tenants: the injected tenant-create failure is replaced by a
  duplicate-ID create (real conflict); the injected tenant-delete failure
  (confirmation stays open) has no server cue; GET /groups/{id} returns no
  member list, so add/remove are asserted on the page's result toasts only;
  the request-body shape checks (PUT body, subject_id wire name) are SDK unit
  test territory; paging seeds tenants up to 51 rather than exactly 60.
- iam-policies: a canned invalid verdict with a named error (the port checks
  whatever verdict the server gives the page's document); a canned allowed
  test result with matched policy and rule (the port checks the server's
  decision); the request-body wire-name checks (spec_yaml, subject_id,
  groups: []) are SDK unit test territory.
- idevid: canned attributes (Infineon, SN-0001), canned CSR bytes, a canned
  LDevID certificate, a flush count of 3 and a canned activated secret; the
  port holds the page to whatever the harness TPM answers. Generate IAK
  leaves an IAK behind (DeleteIAK is refused by the service, by design).
- invitation-accept-flow: the fixed tenant name "Acme Workspace" (the port
  uses the harness tenant's real name); no other gap.
- invitation-accept: the forged numeric-user-ID session is replaced by the
  harness admin's real session; the forged login-issued session
  (operator@platform, no passkey offered) has no harness login to sign in
  with, so that case is not ported.
- invitations: injected 500s on list ("failed to fetch invitations") and
  revoke ("failed to revoke invitation"); the 409 "email already invited" is
  replaced by a real second invite of a seeded email (the port checks
  whatever the server answers); the three tenant-member access-denied cases
  (harness seeds only the admin); the 3 s held-open create (the port takes
  the real server's timing); "no pending invitations" is checked only when
  the server lists none.
- kms-ops: canned result bytes (digest-of-data, mac-of-data, rrrr, plain-dek,
  enc-dek, wrapped-dek) and canned versions (v1 disabled, v2 enabled) are
  replaced by the server's real answers; the "tpm2: healthy" backend line
  is checked only for the backend type the server reports; the injected
  "backend unavailable" failure is replaced by a real HMAC under an unknown
  key.
- iam (part 1 of 3, users, roles, groups): the held-open 500 ms list (loading state);
  mocked user status (mfaVerified active/pending) is replaced by whatever
  status the server gives a fresh user, so the status filter is driven but
  not counted; the empty list is replaced by a search with no match (the
  harness admin is always listed); create-user and delete-user check the
  server's list and get, not a mock store count; group memberships are
  seeded through the SDK but the detail page renders no group list (UI
  gap); "user not found" uses a real unknown ID instead of an injected 404.
  Roles: the mocked create tolerated a new-role route with no form; the
  port checks the server's role list when the form is there and only the
  route otherwise. Groups: create from the page, add member and remove
  member are covered in iam-groups-tenants.spec.ts and not repeated; the
  mocked member counts (10, 5, 8) have no seed call, groups list by name.
- iam (part 2 of 3, permissions, policies, error states, tokens): permissions come from roles
  seeded through the SDK with resources no other role uses; the empty
  permissions list cannot happen (the admin's own role is always there), so
  the port shows a permission leaving the list once its role is deleted;
  the resource filter is checked only when the page renders it. Policies
  are seeded through createPolicy with the YAML the new policy page sends;
  "create a new policy" is covered in iam-policies.spec.ts (CreatePolicy
  from the new policy page) and not repeated; delete checks the server's
  getPolicy, not a mock store count. Error states: the injected 500s on the
  users, roles and groups lists have no server behaviour behind them; the
  port loads the real lists and checks no load error is shown. Create-user
  error is a duplicate email the server refuses (one user with it stays);
  the mocked "cannot delete the last admin" 400 is replaced by deleting a
  user the SDK already deleted (the page shows what the server answers,
  error or success, and the user is gone). The injected 403 "permission
  denied" is a gap: the harness has no member session, so the port opens
  /iam/users with no session and checks the users list is refused.
  Tokens (/iam/tokens): apps are seeded through registerApp and deleted
  through deleteApp; register and rotate check that the dialog shows the
  secret in the server's answer, not a canned one; the clipboard case only
  checks the copy control (no clipboard read). The mocked counts (total 3,
  total 0) become the server's listApps count; the empty table is a search
  with no match (other specs of the worker may leave apps). The injected
  list 500 is replaced by a real load with no error; the 409 duplicate-name
  register by registering a name the server already holds (the page must
  show what the server answered, error or success); the 403 protected-app
  delete and the 500 rotate by acting on an app the SDK already deleted;
  the 500 ms held-open loading state is a gap, the port checks the load
  finishes with no loading text.
- iam (part 3 of 3, applications): apps (/iam/apps) are seeded through
  registerApp, with redirect URIs where a case counts them, and deleted
  through deleteApp. The mocked statistics counts (3, 2, 3) become the
  server's listApps count, the apps it lists with redirect URIs and their
  URI total; the empty state is a search with no match (the zero count is a
  gap: other specs of the worker may leave apps, the port checks the total
  card shows the server's count). "Register application" navigates to
  /iam/apps/new (no dialog on this page). Delete checks listApps no longer
  holds the app, cancel that it still does. The multi-select case checks
  each seeded row has its checkbox, as the mocked one did.

## Out of scope

- Removing `web/e2e/fixtures/*mock*.ts` (other parts still import them).
- Running Playwright in a lane (CI runs the specs).
