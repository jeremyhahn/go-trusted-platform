# Plan: BarrierService on the Embedded transport (#1690)

## Objective

`docs/sdk/api.md` lists `BarrierService` as MISSING on the Embedded
transport. `docs/sdk/architecture.md` requires every service to be reachable
on all six transports or marked MISSING. This row closes the Embedded gap
using only the pinned lower releases (no go.mod change).

## Slices, in order

1. Tests (`test(sdk): ...`)
   - `sdk/go/transport/embedded/dispatch_barrier_test.go`:
     `TestDispatch_Barrier` drives Init, GetStatus, Unseal, Seal and Rekey
     through the handler map to a recording fake server, and checks that a
     registry without a Barrier service registers none of the five methods.
   - `pkg/api/daemon/embedded_host_test.go`:
     `TestNewEmbeddedHost_ServesTheBarrierService` asserts
     `embeddedServices().Barrier` is the daemon's `BarrierGRPCService()`.
2. Change (`feat(sdk): ...`)
   - `ServiceRegistry.Barrier platformv1.BarrierServiceServer` in
     `sdk/go/transport/embedded/adapter.go`.
   - `registerBarrierHandlers` in `dispatch.go`, called from
     `buildHandlerMap`.
   - `Daemon.embeddedServices` sets `Barrier` from the existing
     `BarrierGRPCService()` accessor (the daemon already keeps
     `barrierService`; a node without a barrier manager answers
     Unavailable, as on gRPC).
3. Docs, in the final `feat(sdk): ...` commit (the change landed as a
   `wip:` commit on a checksum stop, CA m2583: no rewrite, one closing
   `feat` commit carries the rest)
   - `docs/sdk/api.md`: Embedded cell for `BarrierService` set to ✅.

## Out of scope

- Any other transport's barrier coverage.
- Lower-module bumps or new barrier-manager APIs.
- The init-only listener's barrier gate.
