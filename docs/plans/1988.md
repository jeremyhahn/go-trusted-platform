# #1988: QUIC denies an operation with no permission and a request with no decision point

## Objective

SPEC row "IAM clean-up, transport checks that allow by default", QUIC part:
`AuthMiddleware.AuthorizeRequest` (`pkg/api/quic/auth.go`) allowed every
request when no AuthorizationChecker was wired, and every operation whose
resource/action pair gives an empty scope. Both now answer PermissionDenied.

## Slices

1. Tests (`test(quic)` commit, `pkg/api/quic/auth_test.go`):
   - no checker, no claims, authenticated token: PermissionDenied;
   - claims path, empty resource/action: PermissionDenied;
   - checker path, empty resource/action: PermissionDenied, checker not asked.
2. Fix (`fix(quic)` commit):
   - `AuthorizeRequest` denies the empty scope on both paths and the nil
     checker, built like the RequireScope refusal;
   - the explicit testing opt-out (`WithQUICRequireAuth(false)`, the
     daemon's SkipIAMValidation) stays: it disables authentication and
     authorization together and is not a "no decision point" default;
   - production caller: `selectQUICAuth` (`pkg/api/daemon/transport_auth.go`)
     built the local-token middleware with no checker, so local tokens
     reached every operation. It now wires `newIAMTokenAuthorizer(local, pep)`
     like gRPC, and refuses the transport when no PEP is wired;
   - tests and fixtures that relied on the open default wire a checker.

## Out of scope

- go.mod/go.sum, SDK bumps, .github/workflows, docs/SPEC.md.
- The other transports of the SPEC row (mTLS gRPC, tenant checks).
