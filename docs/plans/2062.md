# Plan #2062: PXE operations in the web UI (epic #1665 slice 25)

## Objective

Every `PXEService` operation the webservice serves gets a web control that
calls `client.pxe` (no hand-written fetch), with vitest for the hooks and
pages, a capability gate on each control, and a real-server Playwright spec.
The matrix REST `-` for PXEService is a handler-name mismatch: every
operation is already mounted by `pkg/webservice/v1/rest/pxe/router.go`, so no
Go or SDK change is needed.

## Slices

1. Device controls on `networking/pxe`: Authorize (target VLAN), Quarantine
   (reason), Retry and Remove on each All Devices row, through the new
   `usePXEDeviceActions` hook. Tests: `use-pxe-device-actions.test.tsx`
   (SDK arguments, toasts, `onChanged` only on success, `pendingId`) and
   `networking/pxe/page.test.tsx` (each control reaches the SDK through its
   dialog). Matrix rows RemoveDevice, Authorize, Quarantine, Retry to
   `partial` with the served routes.
2. Device detail view on `getDevice` and `getEvents` (event timeline), MAC
   lookup on `getDeviceByMAC`, UpdateState and SetDeviceEnrolled controls,
   Start/Stop service buttons on the status card. Hook and page vitests;
   matrix REST column to the served routes.
3. `<Gated op>` on every PXE control once #2159 (row/2058-ui-ntp) is on
   main; `test/integration/web/pxe.spec.ts` real-server spec; rows to
   `covered`, summary row updated. WebhookComplete is machine-to-machine
   (installer callback, no operator session): marked not-UI.

## Out of scope

- Go changes (pkg/webservice, pkg/api/daemon, pkg/compute/pxe: #1896 and
  #2081 own those files) and sdk/javascript changes.
- The Recent Devices table, the register dialog, the gateway fallback table.
