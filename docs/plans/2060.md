# #2060: DNS UI operations (epic #1665 slice 23, ruling 972)

## Objective

Every DNSService operation the server serves has a web control that calls the
SDK client (`client.dns`), capability-gated, with vitest hook tests and a
real-server Playwright spec, and the coverage matrix rows read `covered`.

## Slices

1. DNSSEC status card and Sign Zone on the zone page.
   - `useDNSSEC(zone)` hook (`client.dns.getDNSSECStatus`, `client.dns.signZone`).
   - `DNSSECStatusCard` on `(dashboard)/networking/dns/[zone]`.
   - Tests: `web/src/hooks/use-dnssec.test.tsx`,
     `web/src/components/features/networking/dnssec-status-card.test.tsx`.
   - Matrix rows SignZone/GetDNSSECStatus to `partial` (no Playwright yet).
   - Sign Zone is ungated until the capability gate (#2159) lands.
2. Records table on `client.dns.listRecords` (a `readRecords` reader in
   `web/src/lib/dns-wire.ts`), a Resolve form (`client.dns.resolve`) and a
   Register form (`client.dns.register`), with hook vitests; Sign Zone,
   Add/Edit/Delete Record and Update Zone wrapped in `<Gated op=...>` once
   #2159 is on main; `test/integration/web/dns.spec.ts` (no page.route);
   matrix rows to `covered` when the spec runs.

## Out of scope

- Go changes (pkg/webservice/v1/rest/dns, pkg/api/daemon) and sdk/javascript
  changes: the routes and the SDK client already exist.
- `web/src/utils/dns-record-type.test.ts` (PR #2124) and the component tests
  the UI epic split train adds.
- A `make web-e2e` target and a real-server Playwright run.
