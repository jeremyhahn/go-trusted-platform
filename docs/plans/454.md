# Plan: #454 drop the REST claim for GetContainerLogs (DS-3803 option b)

## Objective

The Go SDK REST adapter claims `/platform.v1.ComputeService/GetContainerLogs`
as `GET /api/v1/compute/containers/logs`. No server serves that path; the
request lands on `GET /api/v1/compute/containers/{id}` with id="logs".
DS-3803 ruled option (b): drop the claim. Container logs is a server stream,
like AttachContainer, which already carries no REST claim.

## Slices

1. REST claim and its ledgers (this lane, row/454-logs-claim)
   - Test commit: remove the GetContainerLogs entry from
     `claimsResolvingToASiblingRoute` (pkg/webservice/v1) and from
     `daemonDivergentClaims` (pkg/api/daemon); reword `reasonRESTLogs`
     (test/integration/container) so it names no claim.
   - Fix commit: delete the claim from `sdk/go/transport/rest/adapter.go`.
   - Tests: the existing route-claim ledgers (SDKRouteClaims,
     DaemonDivergentClaims, ClaimOperation, RouteCoverage) prove the claim
     and its exemptions are gone together.

2. Later slices (issue stays open): the proto, gRPC, QUIC and MCP handlers
   and docs for container logs.

## Out of scope

The proto, the gRPC service, the QUIC or MCP handlers, the CLI
`container logs` command and the docs.
