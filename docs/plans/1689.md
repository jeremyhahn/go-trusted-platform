# Plan: #1689 MCP tools for daemon get-config and reload-config

## Objective

`docs/daemon/api.md` lists Get config and Reload config with MCP as
`MISSING — docs/13 G7`. The daemon `Service` already answers both over
gRPC (`GetConfig`, `ReloadConfig`). Give them MCP tools with the same
scopes as the gRPC methods.

## Slices (one PR)

1. Tests: `TestDaemonGetConfigTool` and `TestDaemonReloadConfigTool` in
   `pkg/api/mcp/daemon_tools_test.go` (section passed through, empty
   section, provider error unwraps, tool registered); mock methods in
   `pkg/api/mcp/mocks_test.go`.
2. Change:
   - `DaemonGetConfig(ctx, section)` and `DaemonReloadConfig(ctx)` on the
     MCP provider interface (`pkg/api/mcp/types.go`);
   - `MCPServiceProvider` delegates to `Service.GetConfig` and
     `Service.ReloadConfig` (`pkg/api/daemon/mcp_service.go`);
   - tools `platform_daemon_get_config` and
     `platform_daemon_reload_config` registered and dispatched;
   - scopes `platform:read` and `platform:write` in `authz.go`, matching
     `/platform.v1.PlatformDaemon/GetConfig` and `/ReloadConfig` in
     `pkg/api/grpc/method_permissions.go`.
3. Docs: the two `docs/daemon/api.md` rows name the MCP tools.

## Out of scope

- QUIC opcodes, REST routes and CLI commands for these operations.
- Any change to `Service.GetConfig` or `Service.ReloadConfig`.
- go.mod changes or lower-module bumps.
