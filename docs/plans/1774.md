# Plan: JS SDK Gateway service unit tests (#1774, UI epic #1665)

## Objective

Every public method of `sdk/javascript/src/services/gateway-service.ts` has a
unit test on a mocked transport that asserts the HTTP verb, the exact path
(no query string: no Gateway method takes list options), the body, and one
error case (a transport rejection reaches the caller).

## Slices

1. `test(sdk)`: `sdk/javascript/src/services/__tests__/gateway-service.test.ts`
   (next to the other service tests, the vitest convention of this SDK).
   - status: `getStatus`, `setMode`
   - telemetry state: `listState`, `getState`, `deleteState` (id encoded)
   - NAT64: `getNAT64Status` (absolute daemon path, not basePath)
   - BGP: `getBGPStatus`, `listBGPPeers`, `announcePrefix`, `withdrawPrefix`
     (CIDR encoded in the path, no body), `listAnnouncedPrefixes`
   - IPAM: `listIPAMPools`, `allocateIP` (pool in the path, only deviceId
     and hostname in the body), `releaseIP` (IPv6 encoded),
     `listAllocations` (all, one pool, and an empty pool id)
   - one rejection case per method (table-driven).
2. `fix(sdk)`: `listAllocations` treats an empty `poolId` as "all pools",
   as `ListAllocationsRequest` documents, instead of requesting
   `/ipam/pools//allocations`.

## Out of scope

- The other untested SDK services; any Go or server change.
- Pre-existing tsc errors in `src/services/quicbaas/__tests__` and
  `attestation-service.test.ts`.
