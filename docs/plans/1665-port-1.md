# Plan: epic #1665, row #2035: mocked e2e specs, part 1/3, on the real server

## Objective

Port part 1's `web/e2e/*.spec.ts` that import the API mocks to
`web/e2e/real-server/`, on the #2034 harness head (`./fixtures`:
`adminPage`, `sdk`, `tenant`): seed through the SDK, assert on what the
server returns, no `page.route`.

- Done: attest-cert-record (attest-cert-record.spec.ts),
  attestation-reports (attestation-reports.spec.ts), auth (auth-port.spec.ts),
  ca (ca-port.spec.ts), compute (compute.spec.ts) and dashboard
  (dashboard-port.spec.ts); devices (devices-port.spec.ts,
  device-profiles-port.spec.ts, device-idevid-port.spec.ts,
  device-vtpm-port.spec.ts); iam (iam-users-port.spec.ts,
  iam-access-port.spec.ts, iam-tokens-port.spec.ts, iam-apps-port.spec.ts);
  invitations (invitations-port.spec.ts).

## Slices

1. Test commit: add the six ports and this file.
2. Chore commit: delete the six mocked specs they replace.
3. Per describe group of devices, iam and invitations: a static
   <name>-port.check.ts commit, then the <name>-port.spec.ts commit.

which other specs still use; parts 2 and 3 (#2036, #2037); the harness

## Gaps for the route audit

A mocked case with no server state the SDK can seed (no BMC, no TPM
device, no collector report) is ported to assert whatever the server
really answers (success or its refusal shown verbatim); a case with no
server behaviour behind it is listed here.

- attestation-reports: the harness has no collector that can be made to
  produce a report, so the real server cannot answer a collected report in
  any verdict state (fresh, stale, cryptographic failure, a check that could
  not run), the three clock states (synced, unsynced, unknown), the signed
  and TOFU baseline badges, or the new age after a refresh. Those are pinned
  by the component tests device-report-card.test.tsx and
  device-table-attestation.test.tsx against the real SDK client; the port
  asserts what the server answers, including the re-read after Refresh on
  the card and from the fleet row menu. Not covered by either:
  `last-heartbeat-addr`, which needs a heartbeat over mTLS (route audit).
- attest-cert-record, auth and ca: the prior slice that ported them
  recorded no gap for them (its commits say every case reads the server's
  answer); a gap found when CI runs them is added here.
- compute: the VM, container and snapshot cases seed through the SDK
  (createVM, createContainer, createSnapshot); with no compute backend the
  seed is refused and each case asserts the list state the server answers
  (503 SERVICE_NOT_CONFIGURED shows "not available", any other refusal an
  error). Not portable without a server that can be made to answer them:
  the three 503 classification cases (transient 503, registry prose under
  a non-503, 503 without the discriminator) and the delayed-answer loading
  spinner; the page's classification needs a unit test (route audit). The
  three error-state cases merge into the operation cases' refusal branch.
  The tenant-member view needs a second, member account in the harness
  (route audit); the admin view is ported.
- dashboard: the harness's real-server/dashboard.spec.ts ports the rest
  and lists its own gaps (degraded health, network/loading/API-error
  fulfilments, member access, fixed counts). dashboard-port adds the two
  cases it neither ports nor lists: the sections shown once the server has
  answered, and the Certificates stats card link. Member Access "display
  navigation for members" falls under the harness's member-access gap.
- devices-port.spec.ts:
  - should show loading state: the real server answers before the spinner
    can be asserted reliably.
  - refresh attestation enqueues a collection instead of claiming a verdict (#428):
    covered by web/e2e/real-server/attestation-reports.spec.ts:175
  - should handle fetch devices error: needs an injected 500; the real
    server answers an authenticated admin's listing.
  - should allow tenant members to view devices: the harness signs in only
    its admin and cannot create a tenant-member session.
  - refresh attestation from the details page enqueues and re-reads the report (#428):
    covered by web/e2e/real-server/attestation-reports.spec.ts:137
  - should select device type: the create contract stores the serial alone
    (#455); no device type on the server, no type field in the form.
  - should fill TPM information: the create contract takes no
    operator-typed TPM details (#455); the form has no TPM fields.
- device-profiles-port.spec.ts:
  - should handle API errors gracefully: needs an injected 500 on GET
    /device/profiles; the harness cannot make that read fail.
  - should navigate to profile details: no devices/profiles/[id] page; the
    case asserts only the URL the row menu pushes.
  - should navigate to edit profile: no devices/profiles/[id]/edit page;
    the case asserts only the URL the row menu pushes.
  - should handle create profile error: the page validates name, model and
    role first, so the form cannot send a profile the server refuses.
  - should show loading state: the real server answers at once and the
    harness cannot hold a request open.
  - should allow tenant members to view profiles: no tenant-member session

- device-idevid-port.spec.ts:

    daemon's own IDevID key, which other specs read; the server issues no

  - should open actions menu: needs a certificate row; GET /api/v1/idevid

  - should navigate to certificate details: needs a certificate row; the
    server serves no IDevID certificate list.
  - should download certificate: needs a certificate row; no list.
  - should renew certificate: needs an active row; renew regenerates the
    shared daemon's own IDevID.
  - should revoke certificate with confirmation: needs an active row;
    revoke deletes the shared daemon's own IDevID certificate.
  - should cancel revoke when dialog is dismissed: needs an active row; no
    list.
  - should not show renew/revoke for non-active certificates: needs a
    revoked or expired row; no list, no per-certificate status.
  - should handle revoke certificate error: needs a row and an injected
    revoke failure.
  - should handle download certificate error: needs a row and an injected
    download failure.
  - should allow tenant members to view IDevID page: no tenant-member
    session in the harness.
  - should display certificate subject: needs a certificate row; no list.
  - should display serial number in monospace font: needs a certificate
    row; no list.
  - should display formatted dates: needs a row with issued and expiry
    dates; no list.
  - should display multiple certificates: one IDevID per host and no list,
    so never several rows.
- device-vtpm-port.spec.ts:
