# Plan #1846: unit tests for the devices dashboard pages (part 1)

UI epic #1665 support. Web only; no Go change.

## Objective

A vitest + @testing-library test file beside each of these modules, covering
every export with edge, error and invalid inputs, network calls mocked:

- `web/src/app/(dashboard)/devices/[id]/page.tsx`
- `web/src/app/(dashboard)/devices/idevid/[id]/page.tsx`
- `web/src/app/(dashboard)/devices/templates/[id]/create-profile/page.tsx`
- `web/src/app/(dashboard)/devices/idevid/page.tsx`
- `web/src/app/(dashboard)/devices/page.tsx`
- `web/src/app/(dashboard)/devices/profiles/page.tsx`

## Slices

1. The three thin route wrappers: the sibling client component is mocked with
   `vi.mock`; tests check the `generateStaticParams` placeholder and that
   `Page` renders the client component once.
2. `devices/idevid/page.tsx`: list rendering, empty state, load error,
   filters and actions with the SDK/API mocked.
3. `devices/page.tsx`: same pattern for the device list.
4. `devices/profiles/page.tsx`: list, empty and error states, create /
   edit / delete flows and invalid form input.

Each slice is its own `test(web): ... (#1846)` commit. A real bug a test
exposes gets a following `fix(web): ... (#1846)` commit.

## Gates

`make web-deps`, then `npm run test:unit` and `npm run typecheck` in `web`.
Web lint is ungated (#419).

## Out of scope

The client components behind the route wrappers (tested elsewhere), the
other devices pages (templates, vtpm), lint fixes.
