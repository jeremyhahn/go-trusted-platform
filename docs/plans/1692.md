# Plan: SPEC row `luks`, wire the LUKS backend into the daemon (#1692)

## Objective

`docs/SPEC.md` row `luks` asks for LUKS2 key-slot operations as one
platformd service on every transport. The service, the backend
(`pkg/app/backends/luks.go`) and the daemon setters (`SetLUKSBackend`,
`SetLUKSRootChecker`) exist, but no production code calls them, so every
transport answers "not configured". This epic wires them.

## Slices

1. Wire the backend and root checker (this slice).
   - `SDKBackendTarget` gains `SetLUKSBackend` and `SetLUKSRootChecker`.
   - `WireSDKBackends` calls
     `target.SetLUKSBackend(NewLUKSBackend(logger, WithDefaultLUKSHandlers()))`
     and `target.SetLUKSRootChecker(DefaultRootChecker())` after the SDK
     check, so a refused wiring still wires nothing.
   - Test: `TestWireSDKBackends_WiresLUKS` (the recording fake target sees a
     non-nil `*LUKSBackend` and a root checker);
     `TestWireSDKBackends_NoSDKClientIsFatal` also asserts no LUKS wiring.
   - Docs: `docs/luks/engineering.md` §6 and `docs/luks/architecture.md` §3
     describe the wiring.

2. Codex rounds 1-4 (done): keyslot mutations serialized per resolved
   device; `TestUnlock` refuses to claim success from metadata; rotation
   keeps the FIPS KDF policy; FIDO2 enrollment stays off.
3. #649 nil backend (done): slices 1-2 wire it; `docs/luks/api.md` and
   `docs/luks/user.md` no longer say the verbs answer not configured.

4. Codex round 5 (done): REST maps `ErrLUKSPCRInvalid` to 400; production
   wiring leaves TPM enrollment off, as FIDO2 already is, since no boot path
   reads the `systemd-tpm2` token. Tests: `TestLUKSREST_EnrollTPMInvalidPCRs`,
   `TestWireSDKBackends_LeavesTPMEnrollmentOff`.

## Folded items left

- FIDO2 and TPM enrollment with a boot unlock path that consumes the slot
  (an initrd strategy reading the header token, or enrollment onto the
  `luks-root` `.tpmpolicy` record: a design choice for the owner), proven by
  an enrollment-to-boot round trip.

- #748 go-luks2 v1.0.0-rc.2: blocked. `go.mod` holds go-luks2 at
  v0.2.0-alpha because later tags lift go-enclave under go-qrdb, go-xkms and
  go-quicbaas; the bump needs those lower releases first (binding order).
- #28 FIPS activation restrictions (pbkdf2-only keyslots, no SHA-1). New
  keyslots and passphrase rotation are covered: rotation refuses a non-PBKDF2
  or SHA-1 slot (`TestLUKSBackend_ChangePassphraseRefusesSHA1SlotUnderFIPS`).
  What is left is the rest of the issue body, which this lane could not read.
- #1365 initrd FIDO2 metadata persistence.

## Out of scope

- New LUKS operations, handler changes, and integration-test changes.
