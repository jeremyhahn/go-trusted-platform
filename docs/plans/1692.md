# Plan: SPEC row `luks`, wire the LUKS backend into the daemon (#1692)

## Objective

`docs/SPEC.md` row `luks` asks for LUKS2 key-slot operations as one
platformd service on every transport. The service, the backend
(`pkg/app/backends/luks.go`) and the daemon setters (`SetLUKSBackend`,
`SetLUKSRootChecker`) exist, but no production code calls them, so every
transport answers "not configured". This epic wires them.

## Slices

1. Wire the backend and root checker (this slice).
   - `SDKBackendTarget` gains `SetLUKSBackend` and `SetLUKSRootChecker`.
   - `WireSDKBackends` calls
     `target.SetLUKSBackend(NewLUKSBackend(logger, WithDefaultLUKSHandlers()))`
     and `target.SetLUKSRootChecker(DefaultRootChecker())` after the SDK
     check, so a refused wiring still wires nothing.
   - Test: `TestWireSDKBackends_WiresLUKS` (the recording fake target sees a
     non-nil `*LUKSBackend` and a root checker);
     `TestWireSDKBackends_NoSDKClientIsFatal` also asserts no LUKS wiring.
   - Docs: `docs/luks/engineering.md` §6 and `docs/luks/architecture.md` §3
     describe the wiring.

2. Codex rounds 1-4 (done): keyslot mutations serialized per resolved
   device; `TestUnlock` refuses to claim success from metadata; rotation
   keeps the FIPS KDF policy; FIDO2 enrollment stays off.
3. #649 nil backend (done): slices 1-2 wire it; `docs/luks/api.md` and
   `docs/luks/user.md` no longer say the verbs answer not configured.

4. Codex round 5 (done): REST maps `ErrLUKSPCRInvalid` to 400; production
   wiring leaves TPM enrollment off, as FIDO2 already is, since no boot path
   reads the `systemd-tpm2` token. Tests: `TestLUKSREST_EnrollTPMInvalidPCRs`,
   `TestWireSDKBackends_LeavesTPMEnrollmentOff`.

5. Codex round 5 FIDO2 (done): production wiring keeps the FIDO2 handler;
   boot opens a FIDO2 handler when `fido2` is an unlock method, and the
   initrd strategy finds FIDO2 slots from their `fido2-manual` tokens.
   Tests: `TestLUKSFIDO2EnrollmentUnlocksAtBoot`,
   `TestWireSDKBackends_WiresFIDO2Enrollment`, `TestBootFIDO2Handler`.

6. Codex FIDO2 lock (done): calls into the shared SDK FIDO2 handler are
   serialized, and the lock is released by the goroutine running the SDK
   call, so a cancelled caller does not let the next one in early. Tests:
   `TestLUKSBackend_ConcurrentEnrollmentSerializesTheSharedFIDO2Handler`,
   `TestLUKSBackend_CancelledFIDO2DerivationKeepsHandlerLocked`.

7. Codex round 5 cross-process lock (ruling 673, this slice): every keyslot
   mutation holds a per-volume flock on
   `/run/platform/luks-locks/<sha256 of the resolved path>.lock` on top of
   the in-process mutex, so separate backends and processes serialize; the
   device node itself is not flocked (go-luks2 takes its own LOCK_NB lock
   there). The docs say test-unlock refuses without a credential. Tests:
   `TestLUKSVolumeLock_HeldAcrossBackends`,
   `TestLUKSBackend_ConcurrentEnrollmentAcrossBackendsGetsDistinctSlots`,
   `TestLUKSVolumeLock_DirUnwritableFailsClosed`.

8. TPM enrolment (ruling 673): done. An initrd `TPMTokenStrategy`
   reads the `systemd-tpm2` token and unseals with the go-xkms sealer
   (`TokenUnsealer`, `SetUnsealer`); `WireSDKBackends` wires
   `pcrCheckedTPMHandler(luks.TPMHandler())`. Tests:
   `pkg/initrd/strategy_tpm_token_test.go`,
   `TestWireSDKBackends_WiresPCRCheckedTPMEnrollment`, and the
   enrolment-to-boot round trip
   `TestLUKSTPMBootRoundTrip_InitrdUnsealsWhatEnrolmentSealed`
   (`pkg/app/backends/luks_tpm_boot_roundtrip_test.go`).

9. Codex P1 cancellable volume lock (this slice): `lockDevice` takes the
   request context; the in-process wait and the flock wait (non-blocking,
   retried on a short ticker) both end on `ctx.Done()`, and a context that
   ended while waiting releases the lock before any disk mutation. Test:
   `TestLUKSVolumeLock_CancelWhileHeld`. Docs: `docs/luks/cli.md` §1 states
   the startup and hardware prerequisites. Left: the simulator-backed
   enrolment-to-boot round trip through the real SDK sealer (Codex P1 2).

10. Codex P1 no new unlock method (this slice): the exported `tpm-token`
    unlock method is removed; `tpm-pcr` registers the TPM2-Token strategy
    then TPM-PCR, and a configured `tpm-token` is an unknown method. Tests:
    `TestRegisterDefaultStrategies_TPMPCRRegistersTokenStrategy`,
    `TestRegisterDefaultStrategies_TPMTokenIsNotAMethod`. Left: the
    installer FIDO2 token format (Codex P1), held for a ruling.

- Codex round 3 (PR #1894). `PlatformTPMOpener` hands out the platform's
  transport to one sealer at a time: Open waits for the previous closer's
  Close (or returns ctx.Err()), and Close releases once
  (`TestPlatformTPMOpenerSerializes`). The FIDO2 token format (owner item
  239 (a), standard `systemd-fido2` token) is blocked: the pinned go-xkms
  `fido2.Handler` exposes only `UnlockWithKey`, which returns the derived
  key. The raw hmac-secret comes only from
  `(*fido2.HMACSecretExtension).DeriveSecret`, which needs a low-level
  `*fido2.Authenticator` that neither the daemon nor the initrd holds. It
  needs a Handler-level raw hmac-secret call in go-xkms `pkg/fido2`.

## Folded items left

- #748 go-luks2 v1.0.0-rc.2: blocked. `go.mod` holds go-luks2 at
  v0.2.0-alpha because later tags lift go-enclave under go-qrdb, go-xkms and
  go-quicbaas; the bump needs those lower releases first (binding order).
- #28 FIPS activation restrictions (pbkdf2-only keyslots, no SHA-1). New
  keyslots and passphrase rotation are covered: rotation refuses a non-PBKDF2
  or SHA-1 slot (`TestLUKSBackend_ChangePassphraseRefusesSHA1SlotUnderFIPS`).
  What is left is the rest of the issue body, which this lane could not read.
- #1365 initrd FIDO2 metadata persistence: done. The initrd `FIDO2` strategy
  derives the key with hmac-secret, persists the credential and salt in a
  `fido2-manual` token, and reads it at boot
  (`TestFIDO2Install_KeyRecoverableAtBoot` and its siblings in
  `pkg/initrd/strategy_fido2_metadata_test.go`). Backend FIDO2 enrollment
  is wired on top of it (item 5).

## Out of scope

- go.mod bumps or any API beyond the pinned lower tags.
- New LUKS operations, handler changes, and integration-test changes.
