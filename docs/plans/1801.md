# Plan: unit tests for the React useApi and useMutation hooks (#1801)

Part of the UI epic #1665.

## Objective

`sdk/javascript/src/react/hooks/use-api.ts` and `use-mutation.ts` have no
unit test. Cover every export of both modules, including edge, error and
invalid inputs, with `npx vitest run` and `npx tsc --noEmit` green.

## Approach

The SDK carries no React renderer (only `react`; no react-dom, no testing
library) and vitest runs in the node environment. Adding a dependency would
change the lockfile, so each test file mocks `react` with a small
single-component hook runtime (useState, useRef, useCallback, useEffect):
setters schedule a re-render on the microtask queue, effects run after a
render when their deps change, and unmount runs the cleanups.

## Slices

1. `use-api.test.ts`: initial fetch, onSuccess, falsy data, error response,
   rejected fetcher, refetch after error and after success, `enabled`
   (off, refetch no-op, flip on), `initialData`, deps change and length
   change, latest fetcher and callbacks, `mutate` (value, updater, before
   data, stable identity), unmount during a fetch, `refetchInterval`
   (polls, 0 and negative, disabled, stops on unmount).
2. Fix exposed by slice 1: a response with neither `data` nor `error`
   left `isLoading` and `isFetching` true for ever; the hook now settles.
3. `use-mutation.test.ts`: idle state, success with callbacks and order,
   onMutate, error response with and without status, empty response,
   thrown Error, thrown non-Error values, thrown ApiError, `mutate` does
   not reject, `reset`, latest options and mutation function, unmount
   during a mutation.
4. Any fix the mutation tests expose, in its own commit.

## Out of scope

The other hooks in the package, the React context, and any new dev
dependency.
