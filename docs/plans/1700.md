# Plan: #1700 remote-deploy over QUIC

SPEC row `remote-deploy` (docs/SPEC.md Features): "Deploy the remote agent
over QUIC, replacing SSH, FIPS-native."

## Objective

The deploy path is SSH only (`deployer.SSHClient`). Its callers already go
through narrow interfaces (`remoteHost` in `deployer/netboot_media.go`,
`remoteISOClient` in `bootstrap/iso_stager.go`). This epic gives them one
exported seam, `deployer.RemoteHost`, and a QUIC deploy agent that implements
it, so the SSH transport can be replaced without touching the callers.

Lower tags stay as pinned (go-quicbaas v0.12.0-alpha, go-xkms v0.17.0-alpha,
go-qrdb v0.19.0-alpha, go-quicraft v0.13.1-alpha); quic-go is already in
go.mod. No go.mod change.

## Slices

1. (done; SPEC row `in progress`) Seam and agent skeleton.
   - `deployer.RemoteStager` (Run, CopyFileStream) and `deployer.RemoteHost`
     (plus Connect, Close, StatRemote) in `deployer/types.go`, with
     `var _ RemoteHost = (*SSHClient)(nil)`; `remoteHost` and
     `remoteISOClient` become aliases of them.
   - `deployer/quicagent`: `Client` and `Server` over quic-go, one
     bidirectional stream per operation, length-prefixed JSON frames,
     TLS 1.3 mutual auth, P-256/P-384 key exchange only.
   - Tests (loopback UDP, in-memory test CA): Run output and exit status,
     CopyFileStream sha256 match, StatRemote size and not-found, a client
     certificate from another CA is refused and the command never runs.
   - `docs/bootstrap/remote-deploy.md`: the agent and its wire protocol.
2. Certificate issuance for agent and deployer from the platform CA (via
   go-quicbaas), enrolment of the agent identity.
3. (done) Agent install and transport selection.
   - `cmd/deploy-agent` runs the `quicagent.Server` for its whole lifecycle;
     `configs/os/deploy-agent.service` is its systemd unit.
   - `DeployConfig.Transport` (`ssh` default, `quic`) and the
     `pxe_config.go` deployer block select the transport;
     `quicagent.NewRemoteHost` builds the QUIC client from it.
4. (done) Production callers switched over.
   - `LinuxDeployer` (`linux.go`), `deployer_adapter.go` and the ISO
     stager (`iso_stager.go`) dial through `RemoteHost` and no longer
     construct `NewSSHClient` themselves; with `transport: quic` no SSH
     client is built.
   - Small files (the manifest) go through the host's one-command
     `CopyFile` when it has one (SSH) and `CopyFileStream` otherwise
     (QUIC agent).
   - Tests: `TestDeployOverQUICAgentWithoutSSH` deploys through a loopback
     agent with no SSH user, key or known_hosts;
     `TestDeployOverQUICRefusesAnUntrustedAgent` refuses an agent from
     another CA with no SSH fallback.
   - `TestBootstrapQUIC_ReachesDeployerAndISOStager` loads a bootstrap.yaml
     with `transport: quic`, relative agent credential paths and no SSH
     user or key, and checks the DeployConfig both the deployer adapter and
     the ISO stager build carries Transport and every agent field, with the
     paths resolved against bootstrap.yaml's directory (Codex #1899 P1).
     A loopback ISO stage through the agent is still to do: the loopback
     helper lives in package deployer's tests and is not reachable from
     package bootstrap.

## Remaining

Certificate issuance and agent enrolment from the platform CA (slice 2);
making `quic` the default and removing the SSH path, once every target
runs the agent.
