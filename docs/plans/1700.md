# Plan: #1700 remote-deploy over QUIC

SPEC row `remote-deploy` (docs/SPEC.md Features): "Deploy the remote agent
over QUIC, replacing SSH, FIPS-native."

## Objective

The deploy path is SSH only (`deployer.SSHClient`). Its callers already go
through narrow interfaces (`remoteHost` in `deployer/netboot_media.go`,
`remoteISOClient` in `bootstrap/iso_stager.go`). This epic gives them one
exported seam, `deployer.RemoteHost`, and a QUIC deploy agent that implements
it, so the SSH transport can be replaced without touching the callers.

Lower tags stay as pinned (go-quicbaas v0.12.0-alpha, go-xkms v0.17.0-alpha,
go-qrdb v0.19.0-alpha, go-quicraft v0.13.1-alpha); quic-go is already in
go.mod. No go.mod change.

## Slices

1. (this slice) Seam and agent skeleton.
   - `deployer.RemoteStager` (Run, CopyFileStream) and `deployer.RemoteHost`
     (plus Connect, Close, StatRemote) in `deployer/types.go`, with
     `var _ RemoteHost = (*SSHClient)(nil)`; `remoteHost` and
     `remoteISOClient` become aliases of them.
   - `deployer/quicagent`: `Client` and `Server` over quic-go, one
     bidirectional stream per operation, length-prefixed JSON frames,
     TLS 1.3 mutual auth, P-256/P-384 key exchange only.
   - Tests (loopback UDP, in-memory test CA): Run output and exit status,
     CopyFileStream sha256 match, StatRemote size and not-found, a client
     certificate from another CA is refused and the command never runs.
   - `docs/bootstrap/remote-deploy.md`: the agent and its wire protocol.
2. Certificate issuance for agent and deployer from the platform CA (via
   go-quicbaas), enrolment of the agent identity.
3. Agent install and lifecycle on the deploy target (systemd unit,
   bootstrap from the netboot image), selection of the transport in
   `DeployerConfig`.
4. Switch `linux.go` and the ISO stager to the QUIC client by default and
   remove the SSH path.

## Out of scope for slice 1

Certificate issuance, agent installation, config wiring, any SSH removal.
