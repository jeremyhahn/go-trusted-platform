# #1764: platformctl frontend test harness (UI epic #1665)

## Objective

The platformctl desktop frontend (`cmd/platformctl/frontend`) had no test
runner, so none of its calls into the Wails daemon bindings was checked.
Add vitest with `@testing-library/svelte` and jsdom, and unit tests for the
binding wrapper and the two views, with the Wails runtime (`window.go`)
mocked.

## Slices (in order)

1. Tests (`test(platformctl)`):
   - `src/lib/wails.test.ts`: `isWailsReady`, `getDaemonBinding` and
     `getConnectionBinding`, with and without `window.go`.
   - `src/views/Dashboard.test.ts`: load on mount (version, status, health,
     services), Start/Stop/Restart each assert the `StartService`,
     `StopService` and `RestartService` binding call with the service name,
     Refresh re-queries, a binding error shows the error banner.
   - `src/views/ConnectionWizard.test.ts`: protocol change fills the default
     address, Connect passes protocol, address and TLS options, the
     skip-TLS checkbox sends `insecure=true`, a rejected Connect shows the
     error and re-enables the button.
2. Harness (`build(platformctl)`): devDependencies `vitest`,
   `@testing-library/svelte`, `jsdom`, the `test` script, the new
   `package-lock.json`, and a `test` block (jsdom) plus the `svelteTesting`
   plugin in `vite.config.ts`.

## Gates

In `cmd/platformctl/frontend`: `npm ci`, `npm run check`, `npm run build`,
`npm test` all exit 0.

## Out of scope

- Go code and the generated Wails bindings.
- Sidebar, StatusBar and the stores beyond what the views exercise.
- Wiring `npm test` into CI.
