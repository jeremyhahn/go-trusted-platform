# Plan: #1758 UI tenant lifecycle, quotas, sync and DEK rotation (slice 30 of #1665)

## Objective
Every TenantService operation under `/api/v1/tenants` that the web UI lacks
becomes reachable from a page and is exercised by a Playwright test:
GetTenantByName, UpdateTenant, DeleteTenant, SuspendTenant, ResumeTenant,
UpdateQuotas, CheckQuota, Sync, RotateTenantDEK, GetTenantDEKStatus.

## Slices, in order
1. `web/e2e/tenant-lifecycle.spec.ts`: one `test.describe`, a `test.fixme`
   per operation (the test commit, ruling 286).
2. JS SDK: missing methods in `sdk/javascript/src/services/tenant-service.ts`
   with vitest cases (request method, path, body).
3. Web: `web/src/app/(dashboard)/tenant/lifecycle/page.tsx` (by-name
   lookup, edit, quotas, quota check, sync, DEK status) with
   `web/src/hooks/use-tenant-lifecycle.ts`; delete, suspend and DEK
   rotation behind a confirm dialog; a "Lifecycle" entry in the sidebar's
   Tenant group. Departure from the brief: the tenant is picked by name on
   one static route, not an `admin/tenant/[id]` dynamic route (the app is a
   static export, where `[id]` needs a placeholder param); the SDK root
   index gains the tenant type exports.
   SDK fix found on the way: checkQuota and getDEKStatus called
   `/quotas/check` and `/dek/status`; the server serves `/quota-check` and
   `/dek`.
4. Fill the spec: each operation driven through the page against mocked
   API responses (`web/e2e/fixtures/api-mock.ts`).

## Out of scope
- The IAM tenants page under `iam/tenants` (slice 16, #1744).
- Barrier init/unseal/seal (other slices); any Go change.
