# Plan: #2007 VPN gRPC checks the request tenant against the caller tenant (SPEC row 125)

## Objective

`pkg/api/daemon/vpn_grpc_service.go` passed the request tenant to the VPN
control plane with no check against the caller, and an empty tenant listed
every tenant. Every tenant-scoped VPN RPC now calls `authorizeIAMTenant`, so a
tenant-bound caller reaches only its own tenant; a request naming another
tenant, or no tenant, is `PermissionDenied`. A caller with no tenant binding
(Unix peer credentials, SkipIAMValidation) is admitted as before.

## Slices

1. `test(daemon)`: `TestVPNGRPCService_RefusesCrossTenantCaller` drives
   EnrolPeer, ListPeers, RevokePeer, Get/Set/Delete/ListPosturePolicies as a
   tenant-A caller for tenant B and for the empty tenant, and expects
   PermissionDenied; the own tenant is admitted.
2. `fix(daemon)`: call `authorizeIAMTenant(ctx, tenant)` in each method
   before the backend.

## Out of scope

- GetStatus: keyed by gateway, not tenant; no tenant in the request.
- go.mod, go.sum, workflows, other rows.
