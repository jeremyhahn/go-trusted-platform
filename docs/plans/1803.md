# #1803 — web: unit tests for the untested utils

Part of UI epic #1665.

## Objective

Give each of the six modules in `web/src/utils` that has no test a vitest unit
test covering every export, with edge, error and invalid inputs. The tests
follow `web/src/utils/session.test.ts` (vitest, jsdom on an https origin).

## Slices (one commit each)

1. `jwt.test.ts`: `decodeJWT` (all fields, base64url alphabet, padding,
   wrong part count, non-base64, non-JSON, empty payload);
   `getTokenFromCookie` (absent, present); `getUserFromToken` (no token,
   bad token, full mapping, sub over user_id, user_id fallback, defaults,
   missing or empty id, missing email).
2. `cookie.test.ts`: `getCookie` (absent, present, among others, prefix
   names), `setCookie` (encoding, path default and override, max-age,
   expires, the attribute string), `deleteCookie`.
3. `errors.test.ts`: `errorMessage` (Error, empty-message Error, string,
   empty string, other values).
4. `dynamic-route.test.ts`: `resolveDynamicId` (params string and array,
   placeholder, pathname fallback, URL decoding, missing segment, custom
   param name, null inputs).
5. `dns-record-type.test.ts`: `isRecordType`, `toRecordType`,
   `UnsupportedRecordTypeError`.
6. `getBaseUrl.test.ts`: the browser branch (with and without a port) and
   the server branch with `window` stubbed out (defaults, production,
   HOSTNAME and PORT, VERCEL_URL, empty PORT).

A bug a test exposes is fixed in a following `fix(web)` commit.

## Out of scope

- Any change to the modules beyond a fix a test exposes.
- Go code.
