# Plan: #1688 `bootstrap direct` parses and installs the CA bundle

SPEC row: `bootstrap` (docs/SPEC.md Features).

## Objective

`platformctl bootstrap direct --bundle <file>` today only stats the file
(`docs/bootstrap/engineering.md` §7 gap 6). It must validate the bundle as
PEM holding at least one CA certificate and, on request, install it into
the system trust store, as its help text says.

## Slices

1. Tests (`pkg/cli/commands/bootstrap/canonical_modes_test.go`):
   - `TestCanonicalDirect_ValidCABundle`: a self-signed CA PEM is accepted.
   - `TestCanonicalDirect_NotPEM`: a non-PEM file fails with
     `ErrDirectBundleNotPEM`.
   - `TestCanonicalDirect_NonCACert`: a leaf-only bundle fails with
     `ErrDirectBundleNoCA`.
   - `TestCanonicalDirect_InstallToCertPath`: `--install-to-system-trust
     --cert-path <tmp>` writes the bundle to the temp path.
2. Change (`canonical_modes.go`, `errors.go`): decode every PEM block, parse
   each `CERTIFICATE` block with `x509.ParseCertificate`, require one with
   `IsCA`; add `--install-to-system-trust` and `--cert-path` (default
   `defaultCertPath`) calling `trust.InstallToSystemTrust`; typed errors
   `ErrDirectBundleNotPEM`, `ErrDirectBundleInvalidCert`,
   `ErrDirectBundleNoCA`; install failures reuse `ErrTrustInstallFailed`.
3. Docs: `docs/bootstrap/cli.md` §8 describes the new flags and checks;
   gap 6 leaves `docs/bootstrap/engineering.md`.
4. Codex P1 (round 1): a malformed PEM block (truncated, bad base64, missing
   END) before or after a valid CA is refused, not skipped, and an existing
   trust file stays unchanged. Tests `TestCanonicalDirect_RejectsMalformedPEMBlock`
   and `TestCanonicalDirect_AcceptsTwoCAsWithText` (surrounding text is fine).

## Out of scope

- Running OS trust-store update commands (`update-ca-certificates`).
- Recording the bundle as the active trust root in a config file.
- Any go.mod bump; the pinned lower tags suffice.
