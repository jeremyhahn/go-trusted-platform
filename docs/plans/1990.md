# Plan #1990: the route scope guard refuses when no authorizer is wired

## Objective

`scopeRouteGuard.Require` (pkg/webservice/v1/router.go) fails closed: with no
`middleware.ScopeAuthorizer` wired, a guarded application service route
answers 403 instead of falling through to the role gate alone. The unused
`NewAuthzMiddleware` constructor (callers only in its own test) is deleted
with its tests.

## Slices

1. test: `TestScopeRouteGuard` pins 403 for a guard without an authorizer;
   `TestAppServiceRoutes_RefusedWithoutAScopeAuthorizer` pins 403 on every
   app service route under a role-only token handler; the reach test moves
   to a scope-granting token handler.
2. fix: `Require` returns a 403 handler on a nil authorizer; comment updated;
   `NewAuthzMiddleware` and `TestNewAuthzMiddleware` and the tests built on
   it deleted.

## Out of scope

- The other routers' role-gate-alone fallbacks (VPN, PXE, device, CA,
  compute): each has its own `SetScopeAuthorizer`; not this row.
- go.mod, go.sum, workflows, docs/SPEC.md.
