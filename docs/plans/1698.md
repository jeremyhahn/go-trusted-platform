# Plan: #1698 gatewayd hosts the WireGuard VPN plane in the datapath child

SPEC row: `vpn` (docs/SPEC.md Features).

## Objective

`vpn.NewPlaneHost` (`pkg/sdn/gateway/services/vpn/datapath_host.go`) and
`ipc.Server.SetVPNPlanes` (`pkg/sdn/gateway/ipc/server.go`) have no
production caller: the datapath child served by
`pkg/sdn/gateway/commands/service.go` answers every `InstallVPNPeer` with the
`noVPNPlanes` refusal. This row wires the VPN planes into the datapath child
of gatewayd so the peer RPCs reach a real plane.

## Slices

1. WireGuard plane in the datapath child (this slice).
   - `datapathVPNPlanes(def, cfg, gw, logger)` in `commands/service.go`:
     only for the kernel datapath class and only when `management_vpn` is
     enabled; builds a WireGuard plane (`!fips` builds) from
     `tunnel.NewWireGuardHub` with `management_vpn.wireguard.listen-port` and a
     key from `HostRuntime.SecretResolver` (through `resolverKeyProvider`),
     wraps it in `vpn.NewPlaneHost`, and hands it to `server.SetVPNPlanes`
     before `Listen`; the plane is started and stopped with the child.
   - The plane factory sits on the existing `deps` seam so tests inject a
     fake plane.
   - Tests (package `commands`):
     - `TestServeProcess_DatapathHostsVPNPlanes`: an injected fake plane
       answers `InstallVPNPeer` through `ipc.Client`.
     - `TestDatapathVPNPlanes_DisabledLeavesRefusal`: `management_vpn`
       disabled leaves the `noVPNPlanes` refusal in place.
     - `TestDatapathVPNPlanes_NonKernelClassNone`: a non-kernel class gets
       no planes.
   - Docs: `docs/vpn/engineering.md` lines 5 and 89 say the assembly exists.
2. MASQUE plane in the datapath child (later slice).
3. `FactorVerifier` wiring (later slice; needs a go-quicbaas verb not in
   v0.12.0-alpha).

## Out of scope

- MASQUE and `FactorVerifier` (slices 2 and 3).
- Any go.mod change: lower tags stay go-quicbaas v0.12.0-alpha,
  go-xkms v0.17.0-alpha, go-qrdb v0.19.0-alpha, go-quicraft v0.13.1-alpha.
