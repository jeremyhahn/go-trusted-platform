# Plan: #1699, device profile carries the DICE device id and golden FWHash

Row: `device-enrollment` (docs/SPEC.md Features).

## Objective

`docs/firmware/avr-attestation.md` notes that the device profile has no
field for a DICE device id or the golden `FWHash`. This slice adds both to
`entities.DeviceProfile`, validates them on save, lets the profile store
resolve a profile by DICE device id, and exposes both on the
`platformctl device profile create/update` commands.

Lower tags stay as pinned (go-quicbaas v0.12.0-alpha, go-xkms v0.17.0-alpha,
go-qrdb v0.19.0-alpha, go-quicraft v0.13.1-alpha); no go.mod change.

## Slices

1. Entity fields and validation (`pkg/device/entities`)
   - `DICEDeviceID string` (yaml `dice-device-id`): hex, even length,
     1 to 64 bytes.
   - `GoldenFWHash string` (yaml `golden-fw-hash`): hex, exactly 32 bytes.
   - `DeviceProfile.ValidateDICEFields` with typed errors
     `ErrInvalidDICEDeviceID` and `ErrInvalidGoldenFWHash`; called from
     `ProfileService.saveValidated`.
   - Test: `TestDeviceProfile_DICEFieldsValidate` (good, bad length, non-hex).
2. Store lookup (`pkg/device/dao`, `pkg/storage/quicbaas`)
   - `DeviceProfileDAO.FindByDICEDeviceID` beside `FindByEKSerial`
     (case-insensitive), test mocks updated.
   - Test: `TestDeviceProfileDAO_FindByDICEDeviceID_Mock` (hit and miss).
3. CLI (`pkg/cli/commands/device`)
   - `--dice-device-id` and `--golden-fw-hash` on `device profile
     create/update`.
   - Test: `TestProfileDICEFlags_RoundTrip` (flags to create message,
     update set and keep, output map).
   - The CLI speaks gRPC, so this needs `DeviceProfile` proto fields 28
     `dice_device_id` and 29 `golden_fw_hash`, the regenerated
     `sdk/go/gen/device.pb.go`, both-way mapping in
     `pkg/api/daemon/device_grpc_service.go`, and `ProfileService.Update`
     keeping stored values when an update omits them.
4. Docs: `docs/device/cli.md`.
5. Every profile write path carries the fields (Codex rounds on the row PR)
   - REST `ProfileRequest`/`ProfileFullResponse` `dice_device_id` and
     `golden_fw_hash`; MCP profile tools; template overrides.
   - Tests: `TestProfileMapping_CarriesDICEFields`,
     `TestCRUDHandler_UpdateProfile_DICEFieldsRoundTrip` (a PUT that omits
     them keeps them), the MCP dispatch and template service DICE tests.
   - The SDK template override encoder (`sdk/go/services/provision`)
     carries both; `UnassignFromDevice` clears the DICE device id (a device
     binding) and keeps the golden FWHash (a firmware property).
   - Tests: `TestEncodeProfileOverridesJSON_CarriesDICEFields`,
     `TestDeviceTemplateMCP_CreateProfileFromTemplate`, and the
     `ProfileService` DICE tests (invalid Save/Update do not persist,
     omitted values kept, unassign makes the DICE lookup miss).
