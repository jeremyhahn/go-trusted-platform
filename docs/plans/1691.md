# Plan: #1691 SPEC row `policy-engines` — OPA behind one build tag

## Objective

`docs/SPEC.md` asks for "OPA behind one build tag". Today
`pkg/policy/opa/engine.go` and `pkg/compute/container/opa_engine.go`
import OPA unconditionally. Put both behind the `opa` tag, keep the
exported API in a `!opa` stub that returns `ErrOPANotBuilt`, and add `opa`
to the Makefile `BUILD_TAGS` so default builds keep OPA.

## Slices (one PR)

1. Tests (`!opa`):
   - `pkg/policy/opa/engine_noopa_test.go`:
     `TestEngine_NoOPABuild_ReturnsErrOPANotBuilt` — every engine
     method returns `ErrOPANotBuilt` (`errors.As`).
   - `pkg/compute/container/opa_engine_noopa_test.go`:
     `TestOPAEngine_NoOPABuild_ReturnsErrOPANotBuilt` —
     `NewOPAEngine` returns `ErrOPANotBuilt` (`errors.Is`).
2. Change:
   - `//go:build opa` on both engines and their OPA-only tests.
   - `engine_noopa.go` / `opa_engine_noopa.go` (`!opa`) with the
     same exported API.
   - `ErrOPANotBuilt` in each package's untagged `errors.go`, so callers
     can test for it under both tag sets.
   - `Makefile`: `opa` in `BUILD_TAGS`.
3. Docs: `docs/security/engineering.md` records the tag.

`pkg/sdn/gateway/proxysvc/opa.go` uses `opa.NewOPAEngine` and keeps
compiling under both tag sets through the stub. Its OPA evaluator tests
(`opa_test.go`) need the real engine, so that file carries `//go:build opa`.

## Status

The build-tag slice is done. The `!opa` tests pass under an untagged
`go test`. `make test-pkg` passes for `pkg/policy/opa`,
`pkg/compute/container` and `pkg/sdn/gateway/proxysvc`, and so do
`make vet` and `make lint-gates`. `pkg/sdn/gateway/proxysvc` also
compiles without the tag.

Slice 4 (Codex P1, round 1): a CI pass for the `!opa` build.
`make test-noopa` runs `pkg/policy/opa`, `pkg/compute/container` and every
importer of `pkg/policy/opa` (`proxysvc`, `services/vpn`, `sdn/gateway`)
with `opa` dropped from `BUILD_TAGS`; `make test` runs it once (shard 0),
so ci.yml's test step and `test-fips` carry it with no workflow edit. The
real-engine posture tests (`tenant_posture_test.go`,
`vpn_service_opa_test.go`) carry `opa`; `!opa` tests cover the consumers
without an engine (`ErrPostureUnavailable` caused by `ErrOPANotBuilt`, the
tenant fails closed, `NewOPAEvaluator` refuses). Under `!opa` the posture
refusal does not name the tenant: a follow-up for `ErrPostureUnavailable`.

The row stays `in progress` in `docs/SPEC.md`. Its other items still
remain: access decisions folded into go-qrdb ABAC, `pkg/sdn/policy` on
OPA, and Rego held in the datastore with the embedded set as the floor.
