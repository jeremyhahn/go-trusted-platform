# #2037 part 3: real-server e2e ports (epic #1665, ruling 972)

## Objective

Port this part's mocked Playwright specs to the real-server harness
(`web/playwright.real-server.config.ts`, testDir `web/e2e/real-server`):
import only `./fixtures` and `@playwright/test`, seed through the `sdk`
fixture, assert on server state. Each port deletes the mocked spec it
replaces in the same commit. Mocked cases with no server behaviour behind
them are listed below as gaps for the route audit; none is dropped silently.

## Slices

1. Done: tenant-isolation, tenant-management, tenant (now
   `tenant-port.spec.ts`), tpm-attestation, tpm-ops, vpn (now
   `vpn-port.spec.ts`) and vtpm-runtime.
2. Rename the two ports whose names other UI rows also add; this file takes
   the part's gaps out of the shared `docs/plans/1665.md`.
3. Merge `row/1665-ui-e2e-auth` (the harness fixtures).
4. One commit per spec: platform-services, sdn-ports, switch-ports,
   tenant-admin, tenant-lifecycle, tpm-keys, vtpm, devices.

## Gaps

### Slice 1 specs

Forged JWT role/claim sessions, second-tenant switching, injected 500,
network and fetch errors with Retry, delayed-loading states, empty states,
expired/accepted/draft/archived forged statuses, TPM-unavailable and forged
TPM properties, seal/unseal and build error injection, SHA-1 and copy-PCR,
MakeCredential/ActivateCredential canned AK, extend request-body recording,
VPN gateway status card (sessions, refusals, events, leases), cross-tenant
enrolment, vTPM late replies, start/stop serialization and the
daemon-listener /pcr/{index} variant.

### platform-services

- ListServices error card: the mocked 500 ("service manager down") has no
  server behaviour behind it; the real daemon answers the list.
- Service actions run on one listed service (ntp, dns, pxe or vpn first)
  and start it again afterwards; the mocked fixed versions, commits and
  uptimes are replaced by what the daemon returns.

### sdn-ports

- Canned port counters (1234 received, 4500 sent, 7 dropped) and policy
  hit count 42: the port asserts the counter labels the server fills.
- AuthenticatePort with a certificate the harness issued: the port sends
  an unissued PEM and asserts the server's answer (toast only on success).
- RevokePortAuth of an authenticated port: needs the case above.
- No DeletePolicy route in the SDK: policies a test creates are disabled
  through ApplyPolicy afterwards, not deleted.

### switch-ports

- The harness daemon manages no switch and no route adds one, so the port
  table (ListPorts rows), the status panel (link, admin, description from
  the list), enable, disable and set-VLAN dialogs, the trunk port without
  a VLAN form and the three failure toasts have no server behind them.
  The port covers the index form, the unmanaged-switch error with Retry,
  and every port route's refusal through the SDK. A managed (simulated)
  switch in platformd.test.yaml would let them be ported.

### tenant-admin

- Each test creates and deletes its own tenant; the fixture tenant is
  only listed, never suspended, sealed or deleted.
- ListTenants paging past 100 tenants (limit=100, offset=100 and "of 120"):
  seeding 120 tenants per run is not worth the harness time; not ported.
- The canned DEK status line ("Version 1, AES-256-GCM, ACTIVE, usage 1%")
  and rotation 1 to 2: the port asserts the version the server reports and
  its increment.
- CheckQuota forced to "Quota exceeded": the port asserts the request and
  the message that matches the server's availability answer.
- UnsealTenantBarrier with a key the harness holds: the port sends a
  fixed key and asserts the server's answer (success text only on 2xx).

### tenant-lifecycle

- Each test creates and deletes its own tenant.
- Sync with a failed status ("sync completed with errors: boom"): the
  harness sync succeeds and nothing makes it fail; not ported.
- CheckQuota forced to "Not available: quota exceeded": the port asserts
  the request and the result that matches the server's answer.
- The canned DEK version 1 and rotation to 2: the port asserts the version
  the server reports and its increment.

### tpm-keys

- Provision, Clear, CreateEK/SRK/AK and DeleteEK/SRK/AK would replace or
  evict the harness TPM's keys that every other TPM spec uses: the port
  checks each delete and clear dialog's Cancel sends nothing and that the
  create and provision buttons are offered, but never confirms. A
  throwaway TPM per spec (or a reset after the run) would let them be
  ported with their request bodies and result handles.
- ImportEKCertificate with a real certificate: the port sends the mocked
  non-certificate as DER and asserts the server's refusal.
- The canned unbound quote and the forced verified:false verdict
  ("INVALID: nonce mismatch"): the port quotes the real TPM, checks the
  nonce flows into verify and that a verdict shows.
- Capabilities "TPM2_Certify"/"NIST_P256" and "Mock TPM Vendor": the port
  asserts what the server reports.
- The injected 500 on certify: the port certifies a handle the TPM does
  not hold.

### vtpm

- Each test creates its own template or bundle through `sdk.vtpm` and
  deletes it afterwards; start/stop, the running socket path and PCR reads
  stay in `vtpm-runtime.spec.ts`.
- The canned templates tmpl-a/tmpl-b and bundle-1 ("host-one", RSA) and
  their `/var/lib/vtpm/...` paths: the port asserts the paths, hostname and
  EK algorithm the server reports.
- The canned clone answer `bundle-cloned-7`: the port reads the bundle id
  from the server's clone reply.
- ImportBundle of `bundle-imported-9`: the SDK has no export, so there is no
  real archive to import; the port sends the mocked non-archive raw and
  asserts the server's refusal. An export call (or an archive fixture)
  would let the successful import be ported.
- BundleList with 101 bundles: the port does not create 101 bundles; it
  checks the first page asks with no `page=` and, only when the server has
  more than 100 bundles, that Next asks offset 100.
- ValidateBundle forced valid then `checksum mismatch`: the port validates
  once and asserts the verdict the server gives; nothing makes a fresh
  bundle invalid.
- GetTPMSocketPath of a stopped bundle: the port asserts the request and,
  when the server answers a path, that the page shows it.

### devices (part 1 of 2)

`real-server/devices.spec.ts`; each test creates its own devices through
`sdk.device.createDevice` (unique model and serial) and deletes them after.

- Device List: the hardcoded "Online"/"Physical" badges: the port asserts
  the type badge and that a device with no heartbeat is not shown Online.
  The empty state deletes the worker tenant's devices first. The delayed
  500 ms list (loading state) has no server behaviour: the port asserts the
  loading text gives way to the list. The two skipped filter cases (type,
  status) are ported unskipped as "the page has no such filter"; a filter
  UI would need its own case. TPM status asserts "No TPM" only for the
  device without `attest_pub`.
- Device Details: canned attestation history ("passed") and an EK
  certificate (EK-00000001): nothing on the server attests or certifies a
  device created over the API, so the port asserts the empty tabs. Not
  found uses a device deleted through the SDK.
- CRUD Operations: refresh attestation (#428) asserts the server's 202
  enqueue and no verdict; disable asserts the feedback the page shows.
- Error States: the injected list 500 has no server behaviour and is not
  ported (gap). Details error uses an unknown id; the 409 create uses a
  serial the server already holds; the 400 "device in use" delete deletes
  the device behind the page first, so the page's delete fails.
- Access Control: the harness has no tenant member session; the member case
  runs as the tenant admin (gap: a member fixture). The unauthenticated
  redirect uses a fresh context.
- Device Details Actions: the mocked re-read verdict ("Verified") after the
  refresh: no device answers a collection in the harness, so the port
  asserts the never-collected state, the 202 and no verdict.
- Device Form Validation: UI-only, ported as is.
