# Plan: #1950 SDK REST routes for the vTPM template RPCs

## Objective

The Go SDK's REST transport maps the five vTPM template RPCs (create, get,
list, delete, clone) onto the server routes (docs/SPEC.md row), for both the
daemon (`pkg/api/rest`) and the web service (`pkg/webservice/v1/rest/vtpm`).
No server API changes.

## Slices

1. SDK routes and wire decoders (`sdk/go/transport/rest/vtpm_templates.go`,
   `sdk/go/services/vtpm/wire_templates.go`), with unit tests of each route
   and decoder.
2. Round trips against both servers through the SDK
   (`pkg/api/rest/vtpm_templates_sdk_test.go`,
   `pkg/webservice/v1/rest/vtpm/templates_sdk_rest_test.go`); the daemon's
   flat clone reply decodes into the bundle's Manifest.
3. Codex round 2: the daemon's template reply stays as on main. The SDK
   decodes `tpm_state_dir`, `nvram_path`, `secure_boot_keys_dir` only where a
   server sends them (the web service); a daemon reply decodes with empty
   paths. Daemon tests assert the other fields and empty paths. docs/vtpm/api.md
   says which reply carries the paths.

## Out of scope

- Any server handler change, daemon or web service.
- go.mod / go.sum changes, workflows.
