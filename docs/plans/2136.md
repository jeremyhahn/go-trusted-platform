# #2136: server-issued single-use attestation challenge

## Objective

AttestDevice verifies a quote against a nonce the caller chose, so evidence
captured once replays later and still verifies. The server issues the nonce
instead: a single-use, short-lived, tenant- and device-bound challenge that
AttestDevice checks before the (unchanged) quote verifier runs.

## Slices

1. Proto, store, gRPC, REST route (this slice).
   - `DeviceService.IssueAttestationChallenge` and `AttestDeviceRequest.challenge_id`.
   - In-memory `attestChallengeStore` (32-byte nonce, 5 min TTL, consumed on first use).
   - AttestDevice refuses a missing (when `WithDeviceAttestChallengeRequired`),
     unknown, expired, reused, other-device, other-tenant or nonce-mismatched
     challenge before verification.
   - Scope `device:write`; REST `POST /api/v1/devices/{id}/attest/challenge`
     on the v1 router; SDK REST route.
   - Tests: pkg/api/daemon/device_attest_challenge_test.go,
     method_permissions_test.go, device_routes_test.go,
     route_handler_correspondence_test.go, attest_handler_test.go.
2. Required in production.
   - Turn `WithDeviceAttestChallengeRequired` on; move in-process callers that
     send their own nonce (boot_service.go, QUIC and MCP verifyDeviceQuote,
     sdk/go/services/device client, test/integration adapters) onto a challenge.
   - Challenge route on pkg/api/rest (device_handlers.go), PermissionDenied to 403.
   - QUIC and MCP challenge operations; a store that survives restarts and
     works across cluster nodes.

## Out of scope

- Quote verification itself (device_quote_verifier.go, go-xkms) is unchanged.
- The web SDK call, UI flow and gate removal stay in #2134.

## Slice 3 (this branch)

Expired, never-used challenges are swept from the store (objects under
`attest-challenges/`, or in-memory entries) every minute by a ticker the
DeviceGRPCService owns: `Daemon.Start` starts it, `Stop` and `ForceStop`
stop it. A challenge at exactly its expiry is kept; an undecodable record
is kept and logged; a delete another daemon won is not counted.

## Slice 4

`device_attest_challenge` (`device_id` required, `device:write`) answers with
the device service's `IssueAttestationChallengeResponse` (`challenge_id`,
`nonce`, `expires_at`); `Unavailable` with no device service. The SDK MCP
transport maps `IssueAttestationChallenge` to the tool. The challenge stays
optional. QUIC challenge issue waits on the owner (owner queue 266): a new

## Slice 5 (this branch)

MCP `device_attest` takes an optional `challenge_id`. The MCP provider runs
the DeviceGRPCService's `checkAttestChallenge` (through the unexported
`attestChallengeChecker`) before the shared quote verifier, so an MCP attest
consumes the challenge on the first attempt and refuses an unknown, used,
expired, other-device, other-tenant or nonce-mismatched challenge with the
same codes as gRPC, Unix, QUIC and REST. With challenges required, MCP
refuses an attest without one; a `challenge_id` on a daemon with no
challenge service answers `Unavailable`.

## Slice 6 (this branch)

The Go SDK MCP transport maps `AttestDevice` to the `device_attest` tool: it
sends `device_id`, the evidence base64-encoded (standard encoding) and
`challenge_id` only when the caller names one. The tool answers with the
daemon's `DeviceAttestationResult` JSON (decimal-string `device_id`, `status`
rather than `attestation_status`), so the transport decodes it explicitly into
`AttestDeviceResponse` the way the gRPC servicer builds it, with
`Status{Success, "device attestation evaluated"}`; a zero
`pcr_baseline_recorded_at` stays nil ("no baseline").
`cryptographic_failure` has no response field and is not carried.
