# Plan: unit tests for the React domain hooks (#1802)

Part of UI epic #1665.

## Objective

`sdk/javascript/src/react/hooks/` has four modules with no unit test:
`use-eab.ts`, `use-invitation.ts`, `use-device-template.ts` and
`use-provisioning-session.ts`. Add tests that cover every export, including
edge cases, errors and invalid inputs.

## Approach

The SDK has no React renderer in its dev dependencies (no `react-dom` or
testing library), and vitest runs in the `node` environment. Each test mocks
`usePlatformClient`, `useMutation` and `useApi`, then calls the hook as a
plain function and checks the mutation functions and fetchers it builds:
which service method each one calls, with which arguments, which dependency
list and options it passes to `useApi`, and that service rejections come
through unchanged.

## Slices (one commit each)

1. `use-eab.test.ts`: `useEAB` (service, the six mutations, rejection,
   missing provider) and `useEABList` (options mapping, filter dependency list
   and fetcher).
2. `use-invitation.test.ts`: `useInvitation` and `useInvitationList`.
3. `use-device-template.test.ts`: `useDeviceTemplates`.
4. `use-provisioning-session.test.ts`: `useProvisioningSessions`.

If a test exposes a real bug, the fix goes in a separate `fix(sdk)` commit
after the test commit.

## Out of scope

- Changing the hooks, `useMutation` or `useApi`.
- Adding a DOM or React renderer dependency.
- Go code.
