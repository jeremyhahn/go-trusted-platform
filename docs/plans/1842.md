# #1842: unit tests for the iam dashboard pages (part 2)

Objective: a vitest + @testing-library test file beside each of six iam
dashboard modules that have none, covering every export, including edge,
error and invalid inputs, with network calls mocked. Pattern:
`web/src/app/(dashboard)/tenant/invitations/page.test.tsx`.

## Slices (one commit each)

1. `iam/permissions/page.test.tsx`: auth loading, no tenant (fetchers
   reject, no IAM call), each of the three fetch errors, a non-Error
   failure, permission derivation (dedupe, resource grouping, `*` action),
   group/policy row fallbacks, empty replies.
2. `iam/policies/[name]/page.test.tsx`: `generateStaticParams` placeholder,
   `Page` renders the mocked `PolicyDetailClient`.
3. `iam/roles/[id]/page.test.tsx`: same for `RoleDetailClient`.
4. `iam/policies/new/page.test.tsx`: auth loading, Create disabled without a
   name, the YAML built from trimmed comma lists, success toast and route,
   error toast (Error and non-Error), no tenant, Cancel.
5. `iam/roles/new/page.test.tsx`: same shape; role id slugging and the
   permission list.
6. `iam/policies/page.test.tsx`: the list page states and actions.

## Gates

`make web-deps`, then in `web`: `npm run test:unit`, `npm run typecheck`.

## Out of scope

No change to the modules unless a test exposes a real bug (separate
`fix(web)` commit). The detail client components are not re-tested. Lint
is ungated (#419).
