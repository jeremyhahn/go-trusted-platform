# Plan: #1934 SDK REST routes for BMC web certificate and user slots

## Objective

An SDK client on the REST transport can call `GetWebCertificate`,
`DeleteUser` and `SetUserPassword` on `platform.v1.BMCService` and reach the
routes `platformd` already serves, with `profile_id` and `slot` carried in
the path (docs/SPEC.md release criterion: every SDK route matches its
server route).

## Slices

1. Tests (`sdk/go/transport/rest/templated_routes_test.go`), one per method
   against an `httptest` server:
   - `GetWebCertificate` sends `GET /api/v1/bmc/42/cert` and the server's
     envelope fills `Subject`, `NotAfter` and `DaysRemaining`;
   - `DeleteUser` sends `DELETE /api/v1/bmc/42/users/3`;
   - `SetUserPassword` sends `PUT /api/v1/bmc/42/users/3/password` with a
     body carrying `password` and neither `profile_id` nor `slot`;
   - `slot == 0` is refused with `InvalidArgument` before any request.
2. Fix (`sdk/go/transport/rest/adapter.go`): `bmcSlotRoute` beside
   `bmcRoute` (path params `{profileID}` and `{slot}`) and the three
   `templatedRouteTable` entries; docs/bmc/api.md §9 and §12 counts 14 to
   17 and the not-mapped list.

## Out of scope

- `ListUsers`, `CreateUser`, `SetUserPrivilege`, `ReplaceWebCertificate`,
  `EnrollBMC`, `RestoreFactoryCert`: their REST shapes differ from the proto
  and need per-route translation (a separate row).
- Server-side REST changes and the REST BMC scope check (docs/bmc/api.md §8).
