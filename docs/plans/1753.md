# Plan #1753: invitation detail, lookup by token and accept flow (slice 19 of #1665)

## Objective
Every invitation read/accept operation of the backend is reachable from a web page
and exercised by a Playwright e2e test with mocked API responses:

- GetInvitation (`GET /api/v1/invitations/{id}`) -> `/admin/invitations/detail/?id=...`
- GetInvitationByToken (`GET /api/v1/invitations/token/{token}`) -> `/invite/?token=...`
- AcceptInvitation (`POST /api/v1/invitations/accept`) -> `/invite/?token=...`, behind a confirm dialog

## Slices
1. `test(web)`: `web/e2e/invitation-accept.spec.ts`, one or more tests per operation, routed
   through `mockInvitationLookupApi` in `web/e2e/fixtures/api-mock.ts`; vitest wire cases for
   `InvitationService.get`, `getByToken` and `accept` (the SDK already had the methods).
2. `feat(web)`: `useInvitationLookup` hook and fetch helpers in `web/src/hooks/`, the public
   accept page `web/src/app/invite/page.tsx` (outside the dashboard layout, like login), the
   detail page `web/src/app/admin/invitations/detail/page.tsx`, and a "View" link per row in
   the admin invitations list.

## Departure from the brief
- The id and token are query parameters, not `[token]` segments: `next.config.mjs` sets
  `output: 'export'`, which cannot serve an unlisted dynamic segment.
- The accept page is at `app/invite/`, not `app/(dashboard)/invite/`: it is public.

## Out of scope
- Go changes, backend routes, invitation create/revoke/resend (other slices).
