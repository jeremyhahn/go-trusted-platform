# Plan: #1687 — mTLS authenticator fails closed (SPEC row `auth`)

## Objective

Close the two fail-open paths listed in `docs/auth/engineering.md` §4
("Fail-open paths"), items 1 and 2:

1. `MTLSAdapter.Authenticate` skips chain verification when
   `TrustedRoots == nil`.
2. `MTLSAdapter.checkRevocation` treats every `Verify` error that is not a
   revocation as a pass (logged at debug).

Both must fail closed with typed errors. No API beyond the pinned lower
tags is needed; go.mod is unchanged.

## Slices (one PR)

1. Tests (`test(auth): ...`)
   - `TestAuthenticate_NilTrustedRoots_FailsClosed`: an adapter with nil
     `TrustedRoots` refuses a valid certificate with
     `ErrMissingTrustedRoots`.
   - `TestCheckRevocation_NonRevocationError_FailsClosed`: a CA whose
     `Verify` returns a non-revocation error makes `checkRevocation` return
     `ErrRevocationCheckFailed` wrapping that error (`errors.Is`).
   - Existing `Authenticate` cases that relied on nil roots get a root pool
     holding their self-signed leaf.
2. Fix (`fix(auth): ...`)
   - `Authenticate` returns `ErrMissingTrustedRoots{}` when roots are nil.
     The existing typed error (already returned by
     `NewMTLSAdapterFromRoots`) is reused rather than adding a duplicate
     `ErrNoTrustedRoots`.
   - `ErrRevocationCheckFailed` gains an `Err` field and `Unwrap`;
     `checkRevocation` returns it for any non-revocation `Verify` error.
   - Constructor signatures unchanged.
3. Docs (`docs(auth): ...`): §4 items 1 and 2 rewritten as fail-closed.

## Out of scope

- Item 3 (`m.ca == nil` in `checkRevocation`) and item 4 (IDevID) stay as
  documented.
- The existing text match on "revoked" stays (no typed sentinel in the
  pinned go-quicbaas tag is used here); no new string-matched errors.
