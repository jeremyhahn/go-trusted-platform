# Plan #2008: EAB gRPC enforces the caller tenant (SPEC row 125)

## Objective

`EABGRPCService.CreateCredential`, `ListCredentials` and
`CleanupExpiredCredentials` (pkg/api/daemon/eab_grpc_service.go) took
`req.GetTenantId()` unchecked, and an empty tenant on cleanup removed the
expired credentials of every tenant. A tenant-bound caller must reach only
its own tenant: every other tenant, and the all-tenant cleanup, is refused
with `PermissionDenied` through `authorizeIAMTenant`, the rule the IAM gRPC
service already applies. An unbound (local) caller keeps today's behaviour.

## Slices

1. `test(daemon)`: `TestEABGRPCService_CallerTenantBinding` drives the three
   methods with a token caller bound to `tenant-a`: own tenant OK, another
   tenant and the empty tenant PermissionDenied, unbound caller OK.
2. `fix(daemon)`: call `authorizeIAMTenant(ctx, req.GetTenantId())` in the
   three methods before the service call.

## Out of scope

- The other EAB methods (Get, Revoke, Delete, ...) that take a credential id.
- REST, QUIC and MCP EAB surfaces; go.mod, go.sum, workflows.

## Codex round 1 (#2078)

3. `test(daemon)`: an empty-tenant bound caller is refused for every
   method; `TestEABGRPCService_PEPDecision` drives the three methods with a
   stub PEP: an allowed cross-tenant request passes, a denied own-tenant or
   cross-tenant request is PermissionDenied, and the check carries the
   request tenant in `CheckRequest.TenantID` and the caller (subject id,
   OU tenant, roles) in the subject. A PEP error refuses.
4. `fix(daemon)`: `EABGRPCService.SetPEPClient` (optional, wired where the
   daemon has the IAM PEP client). A bound caller with an empty tenant, or
   naming no tenant, is refused; then the PEP decides when configured,
   else `authorizeIAMTenant` equality. Unbound local callers unchanged.
5. `test(daemon)`: mTLS callers reach the PEP as their stored IAM user:
   email SAN via `GetByEmail`, CN via `FindByUsername`, with that user's
   canonical ID and roles; an unknown subject, a user of another tenant, or
   no user directory refuses before the PEP.
6. `fix(daemon)`: `EABGRPCService.SetUserClient` (wired from the IAM
   client's `User()` in the daemon) resolves the mTLS identity before the
   PEP check; token callers are unchanged.
