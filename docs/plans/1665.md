# Epic #1665: the web console against a real server

Ruling 972 (2026-11-19): every UI control is implemented and a Playwright
suite proves it works against the real platform daemon, not `api-mock.ts`.

## Objective

`make web-e2e` builds platformd with the embedded console, starts it on the
in-process TPM simulator with a throwaway data directory, and runs
`web/e2e/real-server/` in Chromium, logging in through real WebAuthn
ceremonies (Chromium's virtual authenticator, no cookie forging).

## Slices, in order

1. **#2034 slice A: harness, make target, auth port.**
   - `web/e2e/real-server/platformd.test.yaml`: web-test config with
     `tpm.simulator: true`, embedded in-memory quicbaas, TLS on 18443.
   - `global-setup.ts`: fresh temp dir, `platformd --init`, wait on
     `/health/ready`; `global-teardown.ts` stops it and removes the dir.
   - `web/playwright.real-server.config.ts`; Makefile `web-e2e`
     (`make build WITH_WEB=1`, then the suite).
   - `auth.spec.ts` ported: forms, protected-route redirects, register,
     log out, log in again, duplicate account, all against the server.
2. **Slice B: real-auth fixtures + dashboard.** A fixture that registers
   (or reuses, via exported virtual-authenticator credentials) a seeded
   admin and one tenant; `dashboard.spec.ts` ported on it.
3. **Slices C..n: the other specs**, a few per slice, each control
   capability-gated and checked against the server's routes (audit #1666);
   gaps found go to the report, not mocks.
4. **CI job** running `make web-e2e` as a required check: a `.github`
   change, Software's; the owner marks it required.

## Out of scope

- `.github` workflows (Software), go.mod/go.sum.
- Deleting the mocked suite: it stays until every spec has a real port.
- Firefox/WebKit: the virtual authenticator is a Chromium CDP feature.
