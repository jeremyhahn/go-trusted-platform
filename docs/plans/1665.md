# Epic #1665: the web UI supports every backend operation

## Objective

Every REST-routed backend operation has a page in the web dashboard and is
exercised by a Playwright e2e test with mocked API responses. The slices
come from the coverage matrix of the audit #1666.

## Slices

### Slice 13: EAB credentials (#1667)

- SDK: `EABService.markUsed(id)` (`POST /credentials/{id}/used`) and
  `EABService.cleanupExpired()` (`POST /credentials/cleanup`), with vitest
  cases for both.
- Hooks: the EAB hooks gain the two new calls.
- Pages: `ca/eab` (list, create, revoke, delete, validate, cleanup expired,
  lookup by key ID) and `ca/eab/[id]` (get, QR code, enrollment URL, mark
  used); a nav entry beside the other CA pages.
- Tests: `web/e2e/eab.spec.ts`, one test per operation, API mocked.

### Slice 18: IDevID and IAK (#1672)

- `web/e2e/idevid.spec.ts`: one test per operation (HasIDevID, HasIAK,
  GetDeviceAttributes, GenerateIAK, DeleteIAK, CreateIAKCSR, CreateLDevID,
  InstallIDevIDCertificate, InstallIAKCertificate, DeleteIAKCertificate,
  FlushTransientContexts, ActivateCredential).
- `web/src/app/(dashboard)/tpm/idevid/page.tsx`: status cards, IAK
  actions, certificate install/delete and maintenance; destructive actions
  behind a confirm dialog.
- An idevid hook in `web/src/hooks/` and a nav entry beside the TPM pages.
- SDK `idevid-service.ts`: only a method that is missing, with a vitest case.

### Slice 23: DNS operations (#2060)

- Operations: GetZone, UpdateZone, SignZone, AddRecord, DeleteRecord,
  UpdateRecord, ListRecords, GetDNSSECStatus, Resolve, Register. Every one
  already has a REST route; no Go change.
- Hook `web/src/hooks/use-dns-ops.ts` (`useDnsOps`) over the SDK DNSService;
  a failed response or a DNSStatus with success false returns null and
  leaves the server's message in `error`. Vitest beside it.
- Zone page: zone settings card (UpdateZone), DNSSEC card (GetDNSSECStatus,
  SignZone disabled with the server's reason when no status is available),
  records panel (ListRecords with type filter, AddRecord, inline
  UpdateRecord, DeleteRecord with confirm).
- Zones page: Register and Resolve cards.
- Spec `web/e2e/real-server/dns.spec.ts` imports `./fixtures` from the
  real-server harness (#2034); it runs once that lands.
- Open: the capability gate (#2033) wraps these controls once it lands.

### Folded: unit tests for the platform dashboard pages

- Vitest files beside `platform/{events,health,logs,metrics}/page.tsx`,
  after the `platform/config` pattern: loading, empty, error and malformed
  input states, filters, refresh, polling, SSE stream and export, with the
  SDK client, fetch and EventSource mocked. No page source changes.

### Base: the failing web unit tests on the row branch

- Page tests follow the current pages: TPM keys and PCRs stub the SDK
  `useTPM`, device templates follow the #1737 dialogs, IDevID and vTPM
  forms expect the SDK wire bodies, tenant reads the token once at mount.
- `components/ui/sidebar.tsx`: `SidebarMenuButton` and
  `SidebarMenuSubButton` set `data-active` from `isActive` (as shadcn
  does), which the `app-sidebar` tests read. No test assertion changed.
- `layout/header.test.tsx` answers `:popover-open`/`:modal` as never
  matching (jsdom has no top layer): floating-ui's `isTopLayer` made jsdom's
  nwsapi take seconds per opened account menu, which tripped vitest's
  `onTaskUpdate` RPC timeout and failed the unit run.
- Acceptance: `npm run test:unit`, `typecheck` and `lint` pass in `web/`.

### Review round 3, Go findings (#1667)

- vTPM bundle import: an expanded-byte budget (256 MiB) and an entry
  budget (4096) on ImportFromFile, a cancellation check per entry, and the
  partial bundle removed on any refusal. Tests lower the budgets.
- Tenant walker: one IAM List with PageSize 0, sorted by ID and paged
  locally, as the embedded SDK ignores PageToken. Tests add an embedded
  paging mode to the IAM mock and reach past 100 tenants.

### Review round 4, vTPM import and verify page (#1667)

- vTPM import: both passes read the decompressed stream through a
  ctx-aware budget reader, so skipped entries (foreign prefix, traversal)
  count against the expanded-byte budget and cancel mid-entry. Tests: a
  64 KiB foreign or traversal entry against a 1024-byte budget, and the
  budget reader's cancel and limit errors.
- Verify page: no verifier call on mount or refetch (VerifyManifest
  without fresh expectations changes quarantine state); history shows
  unverified. Tests: verifyManifest never called, every row Unverified.

## Out of scope

- Go changes beyond the review-round fixes above.
- Slices of other rows of the coverage matrix.
- Redesign or restyling of existing pages.
- InitCA, InstallCACertificates, UninstallCACertificates (no REST route).
- Real-backend e2e (CI integration targets cover the API).
