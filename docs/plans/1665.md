### Go backend slices

1. Go backend (done, the PR's first commit).

   - SDN ApplyPolicy: a failed update of an existing PolicyId re-installs
     the old policy's flows after the rollback deletes the replacements.
     Test: TestSDNService_ApplyPolicy_FailedUpdateRestoresTheActivePolicy.

     normal instance (o.instances, lifecycle Running, wait goroutine), so
     Get, List, Stop and Close see it.

     an active migration stream renews it.

   merge with main: a test commit, then a fix commit.

     the OpenFlow encoder writes, so 10.0.0.1/24 and 10.0.0.0/24 restore
     the same flow.

     waits a bounded time, then kills.

     mapping is removed (the pinned go-quicbaas embedded dispatcher does
     not register quicbaas.IAM.Policy/Simulate).

## Part 2: Plan: epic #1665, UI gated on server capabilities (#2033)

### Objective

The console greys out every control whose operation the server does not
offer right now, with the reason as its tooltip, and shows a "not enabled
on this server" state for a page whose service is off (ruling 972). The
daemon is the source of truth: `GET /api/v1/capabilities` lists what it
actually registered and configured, never a hand-kept list.

### Slices, in order

A. Go endpoint (`pkg/webservice/v1`, this lane).
   - `capabilities.go`: walk the built v1 route table at request time;
     one entry per service the `ServiceRegistry` recorded
     (`kind: service`) and one per method + path template
     (`kind: route`). Each entry has `op`, `enabled` and, when disabled,
     `reason`: `not-configured: <service>` for the routes `requireService`
     mounted with the unavailable-service handler (recorded as they
     register; the service prefix only labels a route), `blocked: integration` for the routes
     `quicbaasStubRoutes` registers (recorded while they register),
     `unimplemented` reserved for handlers that answer 501.
   - Registered authenticated (`authenticatedOnly`), last in `RegisterRoutes`, beside
     `/platform/service-registry` (same wire-state-only data).
   - Tests (`capabilities_test.go`): 200 + JSON envelope on the full
     fixture router; a registered route is enabled; a service turned off
     (nil backend through `requireService`) is `enabled:false` with
     `not-configured: <name>`, and so are its catch-all routes; quicbaas
     stub routes are `blocked: integration`; gateway IPAM routes stay
     enabled with SDN nil and `/platform/service-registry` with the
     platform backend nil; an anonymous request gets 401.
     `routes.golden` gains the new route.
B. `sdk/javascript` `capabilities` service + its unit test.
C. `web`: `useCapabilities()` hook and `<Gated op=...>` wrapper, vitest
   for both.
D. Wire `<Gated>` through the existing pages; the service-off page state.
E. One Playwright spec on the real-server harness: a disabled service
   greys out its controls.

### Out of scope

- Per-caller authorisation in the listing (it reports server wire state,
  not what the caller's role may do).
- Area slices gate the new controls they add themselves.
