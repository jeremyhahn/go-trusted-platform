# Row web (#1665): the web UI supports every backend operation

## Objective

Every backend operation listed in the coverage matrix of #1666
(`docs/ui/coverage-matrix.md`) is reachable from a dashboard page and
exercised by a Playwright e2e test with mocked API responses
(`web/e2e/fixtures/api-mock.ts`). Each slice closes one group of the matrix
and lands through this row's one PR.

## Slices

### CA operations (#1668)

- Pages: `ca/page.tsx` (CA overview from `GET /v1/ca/info`),
  `ca/sign/page.tsx` (`POST /v1/ca/sign-csr`), `ca/verify/page.tsx`
  (verify a PEM certificate).
- The server refuses sign-csr without a platform token holding
  `ca:sign-csr`: the sign page has a required "Platform token" input and
  signs through a per-call `createPlatformClient` carrying the Bearer
  header; the sign-csr mock refuses a request with no
  `Authorization: Bearer` header.
- Tests: `web/e2e/ca-operations.spec.ts`, one test per operation.
- Out of scope: InitCA, InstallCACertificates, UninstallCACertificates (no
  REST route).

### EAB credentials (#1667)

- SDK: `EABService.markUsed(id)` (`POST /credentials/{id}/used`) and
  `EABService.cleanupExpired()` (`POST /credentials/cleanup`), with vitest
  cases.
- Pages: `ca/eab` (list, create, revoke, delete, validate, cleanup expired,
  lookup by key ID) and `ca/eab/[id]` (get, QR code, enrollment URL, mark
  used); a nav entry beside the other CA pages.
- Tests: `web/e2e/eab.spec.ts`, one test per operation.

### IDevID and IAK (#1672)

- `web/src/app/(dashboard)/tpm/idevid/page.tsx`: status cards, IAK actions,
  certificate install and delete, maintenance; destructive actions behind a
  confirm dialog.
- Tests: `web/e2e/idevid.spec.ts`, one test per operation (HasIDevID,
  HasIAK, GetDeviceAttributes, GenerateIAK, DeleteIAK, CreateIAKCSR,
  CreateLDevID, InstallIDevIDCertificate, InstallIAKCertificate,
  DeleteIAKCertificate, FlushTransientContexts, ActivateCredential).

### Invitations (#1671)

- GetInvitation: `web/src/app/(dashboard)/tenant/invitations/[id]/page.tsx`.
- GetInvitationByToken: `web/src/app/(auth)/invite/[token]/page.tsx`. The
  invite page does not call AcceptInvitation: signed-out visitors get the
  passkey sign-up (RegisterInvitedUser joins them); signed-in sessions get a
  notice. Joining an existing account from an invitation needs a server
  operation and is out of scope.
- Tests: `web/e2e/invitation-accept.spec.ts` and
  `invite-accept-client.test.tsx`.

### Tenant lifecycle, quota and DEK (#1673)

- `web/src/app/admin/tenants/page.tsx` (list, create, search, delete) and
  `web/src/app/admin/tenants/[id]/page.tsx` (update, lifecycle, quotas,
  sync, DEK, barrier); destructive actions behind a confirm dialog.
- Tests: `web/e2e/tenant-admin.spec.ts`, one test per operation.

### vTPM bundles and templates (#1674)

- Pages: `vtpm/templates` (list, create, get, clone, delete behind a confirm
  dialog), `vtpm/bundles` (list, import), `vtpm/bundles/[id]` (get,
  validate, bundle, TPM socket and NVRAM paths).
- Tests: `web/e2e/vtpm.spec.ts`, one test per operation.

### Further slices

The remaining matrix groups (BMC, containers, switch ports, IAM policy,
attestation, KMS operations, device templates and profiles, SDN, gateway
BGP and IPAM, platform daemon services, dashboard unit tests) carry their
own plans in `docs/plans/<issue>.md`.

## Gates per slice

`npm run typecheck` and `npm run test:unit` in `web/`; the new spec under
`npx playwright test <spec> --project=chromium`; `npx vitest run` and
`npx tsc --noEmit` in `sdk/javascript` when the SDK changes.

## Out of scope

- Go backend behaviour and API contract changes.
- Visual redesign of existing pages.
- Real-backend e2e (the CI integration targets cover the API).
