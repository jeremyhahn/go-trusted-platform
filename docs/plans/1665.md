# Epic #1665 plan: UI parity with the server (rulings 972, 1024)

## Objective
Every UI route is backed by real server behaviour, every control is
capability-gated, and Playwright specs run against a real server.

## Slices (in order)
1. #2021 Go backend, #2022 JS SDK, #2023 web foundation, #2024 web pages.
2. #2034 real-server harness: `web/e2e/real-server/fixtures` (`adminPage`,
   `sdk`, `tenant`), `make web-e2e`.
3. #2036 port the mocked specs to the harness, in three parts:
   - part 1: specs 1-9; part 2 (this lane, ui2036b): specs 10-17
     (kms, networking, ntp, overlay, platform, provisioning, registry,
     storage); part 3: specs 18-24.
   - tests: one `web/e2e/real-server/<name>.spec.ts` per mocked spec,
     seeded through the SDK, asserting on server answers; then the mocked
     originals are deleted.
4. #2033 capability gate on every page.

## Gaps for the route audit (part 2)
Mocked cases with no server behaviour behind them, dropped from the ports:
- kms: artificial list latency (loading spinner); injected 500 on list,
  detail, rotate and delete; injected 400 on delete; tenant-member session
  (harness seeds only the admin); the skipped encryption-operations block.

## Out of scope
- Writing the harness or the capability gate.
- Removing `web/e2e/fixtures/*mock*.ts` (other parts still import them).
- Running Playwright in a lane (`make web-e2e` runs once #2034 lands).
