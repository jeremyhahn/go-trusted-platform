# Plan: SPEC row `provisioning` — `platformctl pxe` command group (#1694)

## Objective

`docs/provisioning/architecture.md` records that no `platformctl pxe` group
exists, as a gap rather than a decision. The SDK already exposes
`platform.Client.PXE()` (a `platformv1.PXEServiceClient`), so the CLI can
drive the PXE provisioning workflow without any new API in the pinned lower
releases.

## Slices

1. `pkg/cli/commands/pxe/` (this slice)
   - verbs: `list`, `get`, `authorize`, `quarantine`, `retry`, `events`;
   - client from `platform.Client.PXE()` through a replaceable factory;
   - typed errors in `errors.go` (missing device ID, missing reason, an
     unknown `--state`, a failed RPC wrapping its cause);
   - registered in `pkg/cli/commands/root.go`;
   - documented in `docs/provisioning/cli.md` §5.
   - Tests (against a fake `PXEServiceClient`):
     `TestAuthorize_SendsDeviceID`, `TestQuarantine_RequiresReason`,
     `TestList_Table`, plus get/retry/events and the state filter.

## Out of scope

- `register`, `remove`, `update-state`, `set-enrolled`, service
  `status`/`start`/`stop` and the webhook RPC: a later slice of the row.
- Integration targets for the group (REST/MCP transports of the PXE
  service): a later slice.
- Any go.mod change or lower-module bump.
