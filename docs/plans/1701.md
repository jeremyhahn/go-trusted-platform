# Plan: SPEC row `pi-node-roles`, rpi5 control-plane template (#1701)

## Objective

`docs/SPEC.md` asks for control-plane, compute and gateway templates for
raspberrypi, rpi4 first and rpi5 experimental. The gateway role is ruled out
for the one-port Pi (`configs/platform/templates/dedicated/raspberrypi/README.md`).
`rpi5/control-plane.yaml` is missing, so `diskimage create --target rpi
--model rpi5 --role control-plane` is refused. This slice ships it.

## Slices

1. Tests (`test(config): ...`):
   - `pkg/cli/commands/diskimage/create_test.go`: `TestRoleTemplate_RPi5ControlPlane`
     resolves `dedicated/raspberrypi/rpi5/control-plane.yaml`;
     `TestBuildConfigRoleBuildsTheDedicatedTemplate` gains `rpi5/control-plane`.
   - `pkg/config/gateway_role_test.go`: both case maps (gateway role and
     gatewayd packages) list the new file as not a gateway.
   - `TestDecodeHook_ShippedControlPlaneCAKeyPasswords` and the `pkg/ntp`
     template tests walk the template tree, so they pick it up unchanged.
2. Template (`feat(config): ...`): `rpi5/control-plane.yaml`, made from
   `rpi4/control-plane.yaml` with the rpi5 changes `rpi5/compute.yaml` makes
   (hardware-model, IDevID model, serial `rpi5-cp-01`, Ethernet, console and
   TPM comments), marked EXPERIMENTAL.
3. Docs (`docs(config): ...`): README table row and the `rpi5` block.

## Out of scope

- Any go.mod change or lower-module API.
- A gateway template for any Pi (ruled out, one Ethernet port).
- Hardware validation of the Pi 5 (TPM over RP1, console, macb Ethernet).
