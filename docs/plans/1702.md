# Plan: three-node HA control-plane templates (#1702)

## Objective

The x10 high-availability profile ships one control-plane template per
node (`cp1`, `cp2`, `cp3`) so the three nodes form one Raft cluster, and
the profile docs say so.

## Slices, in order

1. test(app): decode the three templates the way platformd does and check
   they form one Raft cluster (`pkg/app/templates_network_test.go`).
2. feat(templates): `configs/platform/templates/high-availability/supermicro/x10/cp{1,2,3}/control-plane.yaml`.
3. docs(templates): the HA profile README and the templates index name the
   three-node control plane.
4. Merge main to keep the PR current (no content change).
5. test(quicbaas): the row's acceptance test,
   `TestShippedHATemplates_FormOneCluster` in `pkg/storage/quicbaas`, decodes
   each template's `quicbaas:` section into `quicbaas.Config` and checks
   Validate, distinct node-ids, shared members and deployment-id, routable
   member addresses and the raft-tls files.
   `TestDecodeHook_ShippedControlPlaneCAKeyPasswords` (`pkg/config`) already
   walks every `control-plane.yaml`, so it covers cp1..cp3 as they are.
6. docs/SPEC.md marks the row shipped.

Gate: `make test-pkg PKG=./pkg/app/`, `./pkg/storage/quicbaas/` and `./pkg/config/`. No feature integration target covers
the templates.

## Out of scope

- Templates for other HA hardware profiles.
- Runtime changes to platformd's Raft bootstrap or membership.
