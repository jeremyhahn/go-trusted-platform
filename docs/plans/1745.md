# Plan #1745: UI for SDN bridge detail, ports and policies (slice 27 of #1665)

## Objective
Every SDN operation with a REST route that the UI does not reach yet gets a page
and a Playwright e2e test with mocked API responses:
DeleteBridge, GetBridge, GetPort, SetPortState, AuthenticatePort, RevokePortAuth,
GetPortStats, ApplyPolicy, GetPolicy, ListPolicies.

## Slices
1. `web/e2e/sdn-ports.spec.ts`: one `test.describe`, a `test.fixme` per operation.
2. JS SDK: missing methods in `sdk/javascript/src/services/sdn-service.ts`, with vitest cases.
3. Web: `networking/sdn/[bridge]/page.tsx` (bridge detail, delete behind a confirm
   dialog, port state/auth/stats, policies), a hook in `web/src/hooks/`, and a
   link from the SDN bridge list.
4. Fill the spec: one test per operation through `page.route` mocks.

5. Codex round 4: Apply Policy sends one rule (action required, priority, protocol,
   source/destination IP, destination port) and a `POLICY_TARGET_TYPE_BRIDGE` target
   for the page's bridge (ApplyPolicy installs flows per bridge target times rules);
   SDK gains rule action/match and target types. The policy dialog is keyed to the
   viewed policy, with loading and error states. Tests: unit (rule + target body,
   refused read after another policy) and the e2e ApplyPolicy body.

## Out of scope
FlushFlows and the other SDN operations without a REST route; network zones (slice 28);
any Go change.
