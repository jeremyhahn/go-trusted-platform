# #2128: CI template v1.48 hosted-first runner selection

## Objective

Take only the ci-template v1.48 runner selection (Tenant Agent rulings 1024
and 1031) into `.github/workflows/ci.yml`: GitHub-hosted runners stay the
default, and a run's jobs overflow to the self-hosted overflow runners
(bigdisk, bigdisk-docker) only when 12 or more hosted jobs of this repository
are in progress, or a hosted job of another run has queued 60 s or more.

## Slices

1. Test commit (`pkg/arch`): `TestCIJobsReadThePreflightRunnerSelection`
   and its mutations pin the env values 12 and 60, the preflight outputs
   `runner` and `runner_docker`, the first preflight step
   `Hosted or overflow runner (ruling 1024)` (id `runner`), and each job's
   runs-on: Docker jobs (lint, integration-image, integration, soak) read
   `runner_docker`, CI Gate reads `runner` with the hosted fallback, the
   other hosted jobs read `runner`; image keeps its oversize waiver. The
   ruling 999 runner test accepts the three selection forms; the race
   routing test resolves the preflight output.
2. Fix commit (`ci.yml`): the env, outputs, step, runs-on lines, and
   `needs: preflight` on signatures.

## Deviation from the template

The selection step keeps a fork pull request on the hosted default (the
self-hosted runners are persistent; ruling 999 keeps forks off them).

## Out of scope

The rest of templates v1.36 to v1.47; the integration failures on main.

## v1.49 preflight runner (DS-9721)

Template v1.49 (Tenant Agent ruling 1047 (3) and (2)) takes preflight out of
the hosted queue it used to wait in for its ten seconds:

- preflight's runs-on is `${{ github.server_url == 'https://github.com' &&
  fromJSON(vars.CI_PREFLIGHT_RUNS_ON || '["self-hosted","linux","x64","bigdisk"]')
  || 'ubuntu-latest' }}`: the bigdisk pool on github.com, `ubuntu-latest` off
  it. The repository variable `CI_PREFLIGHT_RUNS_ON` (runs-on JSON) is the
  switch; `"ubuntu-latest"` (quotes included) puts it back on hosted while the
  pool is down.
- The schedule guard's `BOT` (AGENT_TOKEN) is passed off github.com only; on
  github.com the guard makes no schedule check and reads no tree proof.

Commits:

1. Test commit (`pkg/arch`): `TestPreflightRunsOnTheBigdiskPool` resolves
   preflight's runs-on for the push, PR, fork PR, dispatch and schedule cases
   with the variable unset, set to `"ubuntu-latest"`, and off github.com, and
   pins the guard's BOT; `TestPreflightProblems_Mutations` and new cases in
   `TestSelectionProblems_Mutations`, `TestRunnerProblems_Mutations` and the
   ci tier tests hold the exception to preflight alone.
2. Fix commit (`ci.yml`): the header, the preflight Runner comment and
   runs-on, the selection step's In progress comment, and the guard's BOT.

### Deviation from the template

preflight is the one job that reaches the pool for a fork pull request and
without the schedule guard: it sets up no Go, touches no cache, builds
nothing, checks out with persist-credentials false and reads the tree as text
only, and it is the guard itself, holding a pool slot for about ten seconds.
The runner and tier tests accept that runs-on for the job named preflight
only. The template's Runner labels lint step is not in this repository's
ci.yml; its part F cases are the pkg/arch tests above.
