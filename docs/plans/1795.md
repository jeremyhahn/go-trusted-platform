# Plan: web unit tests for the untested lib helpers (#1795)

Part of the UI epic #1665.

## Objective

Four helpers in `web/src/lib` had no unit test. Add vitest tests in the style
of `log-level.test.ts` that cover every export, including edge and invalid
inputs. Change a helper only if a test exposes a real bug.

## Slices (in order)

1. `device-status.test.ts`: `HEARTBEAT_FRESHNESS_MS`, `deriveDeviceStatus`
   (enforcement states win, exact state match, missing, empty or unparseable
   heartbeat is unknown, the freshness boundary, heartbeats from the future).
2. `utils.test.ts`: `cn` (join, falsy inputs, arrays and objects, Tailwind
   conflict resolution, whitespace).
3. `pcr-baseline.test.ts`: `BASELINE_SOURCE_LABELS`, `baselineSourceLabel`
   (an unknown source passes through), `baselineAge` (missing or unparseable
   time shows an em dash, the default `now`), `baselineRegisters` (register
   order, empty or missing set, non-index keys skipped).
4. `device-profile-networks.test.ts`: `networkPhaseRows` (no networks,
   default and explicit selectors, an empty selector, one key in several
   roles, a selector naming a missing key), `profileOverrides` (all blank,
   trimming, each field alone and together).

## Out of scope

- Changes to the helpers: none of the tests found a bug.
- The `npm run lint` errors that are already on main (react-hooks rules in
  hooks and pages outside `web/src/lib`).
- Go code and the JS SDK.
