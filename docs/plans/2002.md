# Plan: #2002 mTLS tenant from subject OU only (SPEC row 122)

## Objective

The mTLS adapter in `pkg/auth` takes the tenant from the client
certificate's subject OU and nothing else. A certificate with no OU is
refused with `ErrTenantNotFound`: no fallback to the Organization (O),
and no fallback to a configured default tenant.

## Slices

1. `test(auth)`: tests that pin the new behaviour (they fail on main):
   - `TestMTLSAdapter_ExtractTenant`: tenant comes from OU; a certificate
     with O `Acme Corp` and no OU returns `ErrTenantNotFound`.
   - `TestMTLSAdapter_Authenticate`: a certificate with no OU is refused
     even when `DefaultTenant` is set.
   - `TestDefaultMTLSConfig`: `TenantField` is `IdentityFieldOrganizationalUnit`.
   - `TestIdentityField_String`: the OU field prints `organizational_unit`.
2. `fix(auth)`:
   - `pkg/auth/interface.go`: add `IdentityFieldOrganizationalUnit` with a
     `String` case; `DefaultMTLSConfig` sets it as `TenantField`;
     `DefaultTenant` is documented as no longer used for mTLS tenancy.
   - `pkg/auth/mtls.go`: `extractFromField` reads OU; `ExtractTenant`
     drops the Organization fallback; `Authenticate` drops the
     `DefaultTenant` fallback and returns the extraction error.

## Out of scope

- go.mod, go.sum and .github/workflows.
- Removing the `DefaultTenant` field and `WithDefaultTenant` option
  (kept for API compatibility; a later row can delete them).
- Any other SPEC row.
