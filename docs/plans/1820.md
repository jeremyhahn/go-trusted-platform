# Plan: unit tests for the security factor components (#1820)

Part of UI epic #1665. Web only, no Go change.

## Objective

Give the three modules under `web/src/components/security/` unit tests:
`add-factor-wizard.tsx`, `factor-list.tsx` and `vendor-badge.tsx`. Every
export is covered, including edge, error and invalid inputs.

## Slices (in order)

1. `add-factor-wizard.test.tsx` — `AddFactorWizard`: type step gating
   (Next disabled until a type is picked; PIV always disabled; FIDO2
   disabled without WebAuthn), mTLS upload flow to success with
   `authFactorsApi.add` arguments and `onAdded`, blank label rejected,
   mTLS source switch clears the cert, Back, API error shown on the label
   step, rotate mode (`authFactorsApi.rotate`, no Back), closed dialog.
2. `factor-list.test.tsx` — `FactorList`: loading skeleton, empty list,
   revoked factors hidden, grouping by type with counts, Never for an
   unused factor, Rotate callback, Remove via the confirm dialog (confirm
   and cancel), last factor cannot be removed, inline relabel (Enter,
   Save, Escape, blank and unchanged labels ignored).
3. `vendor-badge.test.tsx` — `VendorBadge`: FIDO2 known AAGUID (case
   insensitive), unknown AAGUID with and without a vendor hint, PIV
   subject vendors and fallbacks (subject, card serial, generic), mTLS
   issuer CN and self-issued, className passed through.

## Out of scope

- Changes to the modules themselves (unless a test exposes a real bug,
  which then gets its own `fix(web)` commit).
- The FIDO2 WebAuthn ceremony and the in-browser mTLS cert generation
  (need WebAuthn / WebCrypto plus the issuing endpoint); covered by
  the e2e suite, not here.
