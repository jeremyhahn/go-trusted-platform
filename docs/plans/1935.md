# Plan: #1935 match-rule flags for the pattern, manufacturer and TPM-vendor rules

## Objective

`platformctl device profile create|update` and `device template create|update`
(every verb that calls `registerMatchRuleFlags`) accept `--match-model-pattern`,
`--match-serial-pattern`, `--match-manufacturer` and `--match-tpm-vendor`. As
with the three existing match-rule flags, an update sets only the rules given
and keeps every other stored rule.

## Slices

1. Test commit: `pkg/cli/commands/device/match_rules_test.go`
   - `TestApplyMatchRuleFlags_SetsOnlyGivenRules` sets the four new fields on
     stored rules and checks the other stored rules are kept.
   - `TestApplyMatchRuleFlags_NewRulesOnNil` sets the four fields on nil rules.
   - `TestRegisterMatchRuleFlags_RegistersAllFlags` checks the four flag names
     are registered on a cobra command and parse into `matchRuleFlags`.
2. Fix commit: `pkg/cli/commands/device/match_rules.go` adds the four fields,
   registers the flags, includes them in the "no flag given" check and sets
   each one when given; `docs/device/cli.md` §3.1 flag table gains the four
   rows and §6 drops the sentence about missing flags.

## Out of scope

- `custom_attributes` (a map; needs its own flag syntax).
- Server-side match evaluation and any proto change.
- The by-MAC and by-serial lookup verbs and device activation named in §6.
