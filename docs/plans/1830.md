# #1830: unit tests for the tenant dashboard pages

## Objective

Give each of the four tenant page modules a unit test that covers its only
export (the default page component), including the loading, empty, error and
invalid-input paths.

## Slices (in order)

1. `web/src/app/(dashboard)/tenant/members/page.test.tsx`: IAM user to member
   mapping (name and role fallbacks), singular/plural count, empty, loading
   and error states, retry, list query arguments and `enabled`, role change
   and removal handlers (mutation arguments, success and error toasts,
   refetch, refusal without a tenant), invitation refusal.
2. `web/src/app/(dashboard)/tenant/page.test.tsx`: error state and retry, no
   tenant state, loading skeleton, tenant card (display name fallback, state
   badge, plan, member counts, features, allowed domains), links.
3. `web/src/app/(dashboard)/tenant/quotas/page.test.tsx`: quota rendering,
   loading, empty and error states.
4. `web/src/app/admin/tenant/page.test.tsx`: admin tenant page rendering and
   its handlers.

Each slice is its own `test(web): ... (#1830)` commit. A real bug a test
exposes gets a following `fix(web): ... (#1830)` commit.

## Out of scope

- Changes to the page modules other than a bug fix a test exposes.
- The shared components the pages render (member table, invitation form).
- Go code.
