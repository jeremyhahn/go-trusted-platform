# #1995 — MCP tool permissions from the module declaration, decided by the IAM PEP

Objective (docs/SPEC.md:116): MCP tool authorization comes from the module's
declared tool permissions (`ModuleMCPToolPermissions`) and the IAM PEP decides.

## Slices
1. Done: the unscoped AuthorizeTool path is decided by the IAM PEP (earlier lanes).
2. This slice:
   - test: `TestAuthorizeTool_ModuleDeclaredPermissions` (authz_test.go) — a
     module implementing `MCPToolPermissions()` feeds the checker; the declared
     Permission's resource/action reach PEP Check; an undeclared tool is
     denied; `PermissionIdentityGated` skips the PEP but needs an identity;
     scopes_supported follows the declaration.
   - fix: `WithToolPermissions(module)` option; the platform's tools are the
     `PlatformTools` module declaration (tool_permissions.go), so authz.go has
     no catalogue; oauth_metadata.go advertises from the same declaration and
     never advertises the identity-gated sentinel.

## Known gap
- The pinned go-quicbaas SDK (v0.12.0-alpha) re-exports `Permission` but not
  go-qrdb's `permission.Resource/Action`, and the layer guard forbids importing
  go-qrdb. The resource/action split stays in one helper
  (`permissionResourceAction`) until a quicbaas tag re-exports them.

## Out of scope
- Moving other modules' tools to their own declarations; go.mod bumps.
