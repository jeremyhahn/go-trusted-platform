# Plan: #1734 KMS operations in the web UI (slice 20 of #1665)

## Objective
Every KMS REST operation listed in #1734 is reachable from a dashboard page
and exercised by a Playwright test with mocked API responses.

Operations: ImportKey, UpdateKeyStatus, GetKeyVersions, BatchEncrypt,
BatchDecrypt, Hash, HMAC, VerifyHMAC, GenerateRandom, GenerateDataKey,
GenerateWrappedDataKey, BackendStatus.

## Slices
1. `test(web)`: `web/e2e/kms-ops.spec.ts`, one `test.fixme` per operation.
2. `feat(web)`: `web/src/app/(dashboard)/kms/operations/page.tsx` with one
   card per operation (status change behind a confirm dialog), a hook in
   `web/src/hooks/`, a nav entry next to the KMS pages; the spec's tests
   become real tests that mock the routes and assert the rendered results.
3. The hook calls the REST routes directly (vitest cases in
   `web/src/hooks/use-kms-ops.test.ts`). The JS SDK's `KMSService` has every
   method, but its request types and several paths (status PATCH, `/hmac`,
   `/datakey`) differ from the REST router; that fix changes the SDK wire
   contract and stays out of this slice.

## Gates
`npm run typecheck`, `npm run lint`, `npm run test:unit` in `web/`;
`npx playwright test e2e/kms-ops.spec.ts --project=chromium`.

## Out of scope
Rewrap and the other operations without a REST route; Go changes.
