# Plan: #1734 KMS operations in the web UI (slice 20 of #1665)

## Objective
Every KMS REST operation listed in #1734 that the v1 KMS router serves is
reachable from a dashboard page and exercised by a Playwright test with
mocked API responses.

Operations: ImportKey, UpdateKeyStatus, GetKeyVersions, Hash, HMAC,
VerifyHMAC, GenerateRandom, GenerateDataKey, GenerateWrappedDataKey,
BackendStatus.

## Slices
1. `test(web)`: `web/e2e/kms-ops.spec.ts`, one `test.fixme` per operation.
2. `feat(web)`: `web/src/app/(dashboard)/kms/operations/page.tsx` with one
   card per operation (status change behind a confirm dialog), a hook in
   `web/src/hooks/`, a nav entry next to the KMS pages; the spec's tests
   become real tests that mock the routes and assert the requests and the
   rendered results, including confirm and cancel of the status change.
3. The page calls the v1 routes through the raw ApiClient (vitest cases in
   `web/src/hooks/use-kms-ops.test.ts`); aligning `KMSService` with the v1
   routes is a follow-up.

## Gates
`npm run typecheck`, `npm run lint`, `npm run test:unit` in `web/`;
`npx playwright test e2e/kms-ops.spec.ts --project=chromium`.

## Out of scope
- BatchEncrypt and BatchDecrypt (no route on the v1 KMS router and no JS
  SDK method).
- Rewrap and the other operations without a REST route; Go changes.
