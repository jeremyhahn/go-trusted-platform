# Plan: #1958, IAM policy RPCs over SDK REST

## Objective

The SDK REST transport maps the seven IAM policy RPCs (create, get, list,
update, delete, validate, test) to the tenant-scoped policy routes, and the
production `QuicBaaSIAMAdapter` behind those routes honours what the SDK sends.

## Slices

1. SDK routes and encoders for the policy RPCs (sdk/go/transport/rest), with
   the round-trip test `TestPolicyMethodsOverSDKREST_RoundTrip`. Done in PR #1965.
2. ListPolicies sends pagination as the limit and offset the server reads.
   Done in PR #1965.
3. Codex round 2 (this slice):
   - Test: `TestPolicyMethodsOverSDKREST_ProductionAdapter` serves the
     production adapter over a paged fake upstream (five policies, cursor
     paging) and checks page 2 and 3 of size 2 and the total, and that a
     spec_yaml update is refused with InvalidArgument. The round-trip test
     stops certifying a spec_yaml update.
   - Fix: `QuicBaaSIAMAdapter.ListPolicies` walks the upstream cursor to
     offset+limit, slices the page and propagates TotalCount;
     `UpdatePolicy` refuses a spec_yaml update with `ErrInvalidRequestBody`
     (400 / InvalidArgument) before calling the upstream.
4. Codex round 3, policy labels (this slice):
   - Test: `TestCov964Adapter_PolicyResponsesKeepLabels` gets and lists a
     labeled upstream policy through the production adapter and checks
     decodePolicy copies the label map.
   - Fix: `decodePolicy` sets `Labels: maps.Clone(p.Labels)`.
5. Codex round 4, fixed on the gtp side without an upstream change:
   - Test: `adapter_policy_test.go` against a fake with the embedded
     transport's contract; the production-adapter test's invented cursor
     fake is replaced by the same Limit-only contract.
   - Fix: CreatePolicy refuses rules with `when`/`unless` (400) before the
     upstream; ListPolicies lists the whole collection unlimited, totals it
     and slices [offset, offset+limit); TestPolicy refuses tenant-wide
   evaluation (501). The REST-only `policy_name` this round added is
   removed again in round 5.
6. Codex round 5, fixed on the gtp side without an upstream change:
   - Test: CreatePolicy refuses subject selectors (adapter and SDK REST);
     TestPolicy answers Unimplemented and its body has no `policy_name`.
   - Fix: CreatePolicy refuses a non-empty `spec.subjects`/`subjects`
     (400), which the pinned backend drops and so would apply to every
     subject; `policy_name` is removed so the REST body matches the SDK's
     TestIAMPolicyRequest; TestPolicy always answers 501, since the pinned
     service evaluates only a named policy and the SDK request names none.

## Out of scope

- The daemon gRPC `IAMGRPCService.ListPolicies` and `UpdatePolicy`, which
  share the offset and spec_yaml gaps (a later row).
- A YAML policy update upstream (the pinned SDK has no SpecYAML on update).
- go.mod / go.sum changes, workflows.
