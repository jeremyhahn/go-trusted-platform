# Plan: #1723 container registry UI (slice 26 of #1665)

## Objective
The web UI reaches every container registry REST operation:
List (`GET /{name}/tags/list`), Delete (`DELETE /{name}/manifests/{reference}`)
and Status (`GET /status`), with Playwright e2e on mocked API responses.

## Slices
1. Spec first: `web/e2e/registry.spec.ts`, one `test.fixme` per operation.
2. SDK: `sdk/javascript/src/services/registry-service.ts` (shape of
   `dns-service.ts`), exported from the services index, vitest cases for
   each method (URL, method, response mapping).
3. Web: a registry hook in `web/src/hooks/`, the page
   `web/src/app/(dashboard)/compute/registry/page.tsx` (status card, tag list
   per repository, delete behind a confirm dialog) and a nav entry beside the
   other compute pages.
4. Fill the spec: one test per operation, mocks through
   `web/e2e/fixtures/api-mock.ts`.

## Out of scope
- Inspect (no REST route yet); Push and Pull (streaming, not UI).
- Any Go change.
