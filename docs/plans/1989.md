# Plan #1989: mTLS calls get a per-method PEP check, no wildcard grant

## Objective

An mTLS-authenticated caller is authorized per operation by the IAM PEP
(`quicbaassdk.IAMPEPClient.Check`) for the certificate principal, not by the
`mtlsOperatorScope = "*:*"` grant in `pkg/api/daemon/transport_auth.go`.
No PEP wired, or PEP denies -> PermissionDenied.

## Findings (slice 0)

- gRPC: `MTLSUnaryInterceptor` / `MTLSStreamInterceptor`
  (`pkg/api/daemon/mtls_interceptor.go`) authenticate only.
  `selectGRPCTCPAuth` already receives `pep`.
- Method -> scope: `grpcapi.ScopeForMethod(fullMethod)` returns
  `"resource:action"` (`pkg/api/grpc/method_permissions.go`); split with
  `strings.Cut(scope, ":")` as `oidc_interceptor.go` does.
- PEP call helper exists: `checkPrincipalPermission(ctx, pep,
  &tokenPrincipal{Subject, TenantID, Roles}, resource, action)`
  in `pkg/api/daemon/quic_iam_authorizer.go` (returns ErrPEPClientNotAvailable
  when pep is nil).
- The `"*:*"` grant lives in `mtlsPeerAuthenticator.AuthenticatePeer`, which
  QUIC (`selectQUICAuth`), REST (`newRESTScopeGuard`) and MCP
  (`newMCPPeerAuthenticator`) also use; their callers check scopes with
  `authCtx.RequireScope` (`pkg/api/mcp/authz.go:911`,
  `pkg/api/rest/route_scope.go`, `pkg/api/quic/peer_auth.go`). Dropping the
  grant breaks those three mTLS paths unless each gets a PEP decision point.

## Slices

1. gRPC (this brief): `MTLSInterceptorConfig` gains `PEP` and a
   `Permission func(string) string` (default `grpcapi.ScopeForMethod`); after
   authentication: unmapped method, nil PEP, or deny -> PermissionDenied;
   PEP error -> Unavailable. `selectGRPCTCPAuth` passes `pep`.
   Tests in `mtls_interceptor_test.go`: fake PEP deny -> PermissionDenied,
   grant -> handler runs, nil PEP -> PermissionDenied (unary and stream).
   Status: done (fix(daemon) commit).
2. QUIC/REST/MCP (open, not in the gRPC lane): `mtlsOperatorScope` stays
   until these callers consult the PEP, since dropping it would lock the
   operator out of them: `pkg/api/quic/auth.go:290`,
   `pkg/api/quic/phase35_auth.go:65`, `pkg/api/rest/route_scope.go:131`,
   `pkg/api/daemon/rest_scope.go:263`, `pkg/api/daemon/iam_rest.go:107`,
   `pkg/api/daemon/device_rest.go:44`, `pkg/api/mcp/authz.go:911`.
   QUIC already has `WithQUICAuthorizationChecker` (unused by the daemon). Give `mtlsPeerAuthenticator` the PEP and make the scope
   check consult it (or empty Scopes plus a PEP-backed checker in each
   guard), then delete `mtlsOperatorScope`; `mcp_peer_auth_test.go:48` and
   `iam_rest_test.go:45-46` fake a granting PEP instead.
