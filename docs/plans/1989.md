# Plan: #1989 mTLS gRPC calls get per-method IAM authorization

## Objective

Every mTLS gRPC call, except the classified pre-auth methods, is decided by
the IAM policy enforcement point (PEP) on the certificate principal's stored
IAM identity: its stored user ID and its IAM roles. A certificate carries no
roles of its own. PR #2015 carries the row.

## Slices, in order

1. Done (earlier lanes): the mTLS interceptors run a PEP check per method and
   skip the classified pre-auth methods. Tests: TestMTLSInterceptorsPEPCheck.
2. Done (earlier lanes): the certificate's email SAN or CN is looked up in
   IAM (GetByEmail or FindByUsername, no fallback) and the user's roles go to
   the PEP. Tests: TestIAMUserPrincipal_LooksUpEmailAndUsername.
3. This lane (Codex round 4, ruling 948): the resolver also returns the
   stored user ID, and the PEP check's Subject is that ID, so ABAC user
   selectors on the stored ID match. An empty ID or a missing user record
   refuses the call.
   - MTLSInterceptorConfig.Roles becomes Principal (user ID, roles, error).
   - iamUserRoles becomes iamUserPrincipal.
   - Tests: TestMTLS_PEPSubjectIsTheStoredUserID (subject 123 seen by the
     PEP, a deny rule on 123 refuses, an empty ID refuses), and the new
     resolver cases (no ID, no user record).
