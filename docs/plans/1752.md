# Plan: #1752 UI platform daemon services (slice 10 of #1665)

## Objective
Every platform daemon REST operation is reachable from the web UI and covered
by a Playwright e2e test with mocked API responses.

Operations: GetStatus (`GET /status`), GetVersion (`GET /version`),
GetConfig (`GET /config`), ReloadConfig (`POST /config/reload`),
ListServices (`GET /services`), GetServiceStatus (`GET /services/{service}`),
StartService, StopService, RestartService (`POST /services/{service}/{action}`).

## Slices
1. `web/e2e/platform-services.spec.ts`: one `test.describe`, a `test.fixme`
   per operation (test first, ruling 286).
2. JS SDK `platform-service.ts`: add the missing methods, with vitest cases.
3. Web: hook in `web/src/hooks/` and `platform/services/page.tsx` showing
   status, version, config, reload, the service list, per-service status and
   start/stop/restart; stop and restart behind a confirm dialog; nav entry (already present: Platform > Services).
   Vitest `platform/services/page.test.tsx` pins confirm and cancel.
4. Fill the spec: one test per operation, the daemon routes mocked by
   `mockPlatformDaemonApi` in `web/e2e/fixtures/api-mock.ts`. The old
   health-derived "Services Page" block in `e2e/platform.spec.ts` goes: the
   page no longer reads `/health`, and the new spec covers it.

Codex follow-ups: lifecycle POSTs go out with SDK retries off (a lost
response must not resend a stop or restart), and the hook sequences
service-list reads so a read started before an action never lands after it.

The nav entry (`/platform/services` in `app-sidebar.tsx`) already existed.

## Out of scope
Liveness, Readiness, Shutdown and UpdateConfig (no REST route). No Go change.
