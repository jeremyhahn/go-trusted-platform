# Plan: SPEC row `auth` (#646)

## Objective

One user store on go-quicbaas IAM; login, logout and mTLS sign-in work.
The row's acceptance (docs/SPEC.md) holds and every folded checklist item
is done, each with a test that fails before and passes after.

## Slices, in order

1. **#642 — a signed-in account is retrievable.** A backbone-issued
   session (from the unified login driver) carries no platform `uid`, so
   `/login/refresh` and `/session` refused every user who signed in
   through the backbone. `pkg/webservice/v1/jwt/handler.go` resolves the
   session's user by the principal it names: the platform id for a
   platform token, the backbone subject (the key registration stores and
   the FIDO2 binder resolves the workspace with) for a backbone session,
   and fails closed when the subject is gone or sits in another tenant.
   Tests: refresh and session of a backbone session succeed; a missing
   user and a cross-tenant subject are refused.
2. **#664** — backbone session carries the workspace owner flag (needs
   the owner ruling named in the issue; reversible default until then).
3. **#215** — logout revokes the session server-side (deny-list keyed by
   `jti`), not only the cookie. Test: a token used after logout is 401.
4. **#201** — the console already signs in through `/api/v1/login`; the
   webservice now serves `HEAD /api/v1/auth/mtls/probe` from the same
   login driver (`Driver.Probe`): 501 while the mTLS binder declines
   (go-quicbaas#857, not in the pinned v0.12.0-alpha), 401 with no client
   certificate, 204 when the login would start. Certificate login itself
   opens when #857 is consumed by tag.
5. **#1107** — mTLS peer authenticators map the certificate to its
   principal's scopes instead of `*:*`.
6. **#180 / #283** — admin registration offers certificate, FIDO2, PIV
   through the SDK admin factor; hardware residue reported, not faked.
7. **#172** — admin-claim atomicity: SDK gap, reported upstream-shaped.
8. **#1382 / #928** — IAM REST adapter audit and the one-authorization-
   model audit.
9. **Phase 3 of #646** — delete the platform user DAO as a store of
   record (`pkg/platform/service/user.go`, `pkg/storage/quicbaas/user.go`,
   `pkg/store/datastore/kvstore/user.go`), IAM only; mark the row shipped
   in docs/SPEC.md.
