# Plan: SPEC row `auth` (#646)

## Objective

One user store on go-quicbaas IAM; login, logout and mTLS sign-in work.
The row's acceptance (docs/SPEC.md) holds and every folded checklist item
is done, each with a test that fails before and passes after.

## Slices, in order

1. **#642 — a signed-in account is retrievable.** A backbone-issued
   session (from the unified login driver) carries no platform `uid`, so
   `/login/refresh` and `/session` refused every user who signed in
   through the backbone. `pkg/webservice/v1/jwt/handler.go` resolves the
   session's user by the principal it names: the platform id for a
   platform token, the backbone subject (the key registration stores and
   the FIDO2 binder resolves the workspace with) for a backbone session,
   and fails closed when the subject is gone or sits in another tenant.
   Tests: refresh and session of a backbone session succeed; a missing
   user and a cross-tenant subject are refused.
2. **#664** — backbone session carries the workspace owner flag (needs
   the owner ruling named in the issue; reversible default until then).
3. **#215** — logout revokes the session server-side (deny-list keyed by
   `jti`), not only the cookie. Test: a token used after logout is 401.
   The deny-list persists in the daemon's blob store (WebAuthn session
   DAO, `jwt.BlobRevocationStore`) until the token expires, so it holds
   after a restart and on every instance. Test: a second Service over the
   same store refuses the revoked token; an unreachable store fails closed.
4. **#201** — the console already signs in through `/api/v1/login`; the
   webservice now serves `HEAD /api/v1/auth/mtls/probe` from the same
   login driver (`Driver.Probe`): 501 while the mTLS binder declines
   (go-quicbaas#857, not in the pinned v0.12.0-alpha), 401 with no client
   certificate, 204 when the login would start. Certificate login itself
   opens when #857 is consumed by tag.
5. **#1107** — the QUIC, REST and MCP mTLS peer authenticator resolves
   the certificate (CN in its O tenant) to its IAM user and grants that
   user's role permissions instead of `*:*`; no active principal, no
   admission (`pkg/api/daemon/mtls_principal.go`). The lookup goes
   through `pkg/auth/iamuser` (CN by username, email SAN by email), since
   the pinned embedded transport registers only User/Get and User/List.
   Its User/List returns one page (the store's 100) with no token and
   drops PageSize, and no registered method pages further, so a lookup
   that misses on a full untokened page fails closed with
   `iamuser.ErrTruncated`, never not-found. Tests: CN and email-SAN
   principals resolve over the real embedded SDK client; a tenant over
   100 users gets the truncated error. The PEP decides each concrete
   `resource:action` permission. A whole-segment wildcard (`piv:*`,
   `*:read`, `*:*`) is expanded against the platform's concrete catalog
   (gRPC, QUIC and MCP scopes plus REST read/write/delete per resource)
   and the PEP decides each expansion; a pattern is never a scope and a
   partial glob grants nothing (Codex round 4, finding 1). Tests: a `*:*`
   role with a PEP denying `device:write` yields every other catalog
   permission; `piv:*` over mTLS grants `piv:use`.
   The pinned embedded transport answers every PEP check with "IAM.PEP
   not configured", so the certificate resolver asks the app's own policy
   engine (`app.IAMProvider.GetPolicyEngine`) through `policyEnginePEP`
   (`pkg/api/daemon/iam_policy_engine_pep.go`), falling back to the SDK
   PEP only when no engine is reachable (Codex finding 2 on #1906).
   Tests: a real `iam.NewPolicyEngine` allows and denies through the
   adapter; a nil engine denies; `certificatePrincipalPEP` picks the
   adapter for an IAMProvider service and the fallback otherwise.
6. **#180 / #283** — admin registration offers certificate, FIDO2, PIV
   through the SDK admin factor; hardware residue reported, not faked.
7. **#172** — admin-claim completion is atomic across instances: a
   compare-and-swap lease on the store (`adminclaim/completion.go`) lets
   one instance at a time read the factor history and enrol; others get
   409 `ErrClaimInProgress`, a store that cannot run it fails closed.
   A multi-instance deployment stays refused (`ErrMultiInstanceUnsupported`,
   501) on all four mutating paths whatever `ProbeTransactions` answers:
   the lease cannot fence a delayed enrolment, so fencing the enrolment
   write on the lease is the prerequisite for clustered claims.
8. **#1382 / #928** — IAM REST adapter audit and the one-authorization-
   model audit.
9. **Phase 3 of #646** — delete the platform user DAO as a store of
   record (`pkg/platform/service/user.go`, `pkg/storage/quicbaas/user.go`,
   `pkg/store/datastore/kvstore/user.go`), IAM only; mark the row shipped
   in docs/SPEC.md. Done first: a backbone session refreshes from its
   IAM tenant (`WorkspaceRoleResolver.Principal`), never the platform
   store. Left: session creation, adminclaim's admin record, WebAuthn
   registration, invitations, then the DAO deletion itself.
10. **Logout is surfaced (PR #1906 review)** — a revocation store that
   cannot be read or written answers logout with 503
   (`ErrRevocationUnavailable`), not 401; `revokeSession` resolves to
   revoked/rejected/failed/none, and on "failed" `useLogout` keeps the
   bearer and the logout page offers "Retry sign-out" or a browser-only
   sign-out. Tests: logout_test 503 case, session/use-logout/logout page
   vitest cases.
