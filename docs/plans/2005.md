# Plan: #2005, IAM middleware takes the tenant only from the principal (SPEC row 123)

## Objective

`pkg/webservice/v1/middleware/iam` resolves a request's tenant from the
authenticated principal only: the JWT `tenant_id` claim, or the client
certificate's first subject OU. A request whose principal names no tenant
is refused with `ErrMissingTenantID`, whatever the `X-Tenant-ID` header or
the server configuration says. The MCP QuicBaaS auth adapter
(`pkg/api/mcp`, also row #2004) likewise takes the tenant only from the
token.

## Slices

1. Tests (`test(webservice/iam)`, Refs #2005) in `auth_test.go`:
   - a JWT with no `tenant_id` plus an `X-Tenant-ID` header gives
     `ErrMissingTenantID`;
   - a JWT with no `tenant_id` and no tenant anywhere else gives
     `ErrMissingTenantID`;
   - an mTLS certificate naming no tenant gives `ErrMissingTenantID`.
2. Fix (`fix(webservice/iam)`, Refs #2005): drop the header read and the
   `DefaultTenantID` fallback in `auth.go`; drop `TenantIDHeader` and
   `AuthConfig.DefaultTenantID` in `types.go`.
3. Codex round 1 (#2080), tests (`test(iam,mcp)`):
   - a certificate with no OU is refused even with O, CN and SANs set; one
     whose O and OU differ takes the OU;
   - MCP `CheckPermission` refuses a token with no tenant
     (`QuicBaaSAuthErrorMissingTenant`, PEP not asked) and its
     `CheckRequest.TenantID` is the token's tenant.
4. Fixes:
   - `fix(iam)`: `extractTenantFromCert` returns only the subject OU;
     `AuthConfig` drops `ExtractTenantFromCert` and `TenantCertField`;
   - `fix(mcp)`: `CheckPermission` refuses an empty token tenant and sets
     `CheckRequest.TenantID`; `DefaultTenantID`, `defaultTenantID` and
     `SetDefaultTenantID` go (Refs #2005, Refs #2004).
5. Codex round 2 (#2080): the daemon's MCP token validator
   (`quicbaasServiceWrapper`) carries the verified tenant.
   - `test(daemon)`: a verified token naming a tenant reaches the PEP with
     it; one naming none is refused with the missing-tenant error.
   - `fix(daemon)`: `quicbaas.ValidateTokenResponse.TenantID`, filled by
     `quicbaasServiceAdapter` from the `tenant_id` claim of the token the
     service has just verified (go-quicbaas returns no tenant), copied
     into `mcp.TokenValidationResult` by the wrapper. Never a header.
6. Codex round 3 (#2080):
   - `test(mcp,daemon)`: `Authenticate` (tools/list, resources/list)
     refuses a verified token naming no tenant; the daemon test drives a
     stub `service.QuicBaaS` through `quicbaasServiceAdapter` (accepted
     with and without tenant, rejected, validation error) to the PEP.
   - `fix(mcp)`: `QuicBaaSAuthAdapter.ValidateToken` returns the
     missing-tenant error for a tenantless token and does not cache it.
   - `refactor(iam)`: `auth.go` (`NewAuthMiddleware`, `AuthMiddleware`)
     and its tests go, as SPEC row 123 states.
7. Round 4: AuthorizeTool sets CheckRequest.TenantID from the principal.
