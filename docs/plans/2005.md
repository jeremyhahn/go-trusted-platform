# Plan: #2005, IAM middleware takes the tenant only from the principal (SPEC row 123)

## Objective

`pkg/webservice/v1/middleware/iam` resolves a request's tenant from the
authenticated principal only: the JWT `tenant_id` claim, or the client
certificate field `TenantCertField` names. A request whose principal names
no tenant is refused with `ErrMissingTenantID`, whatever the `X-Tenant-ID`
header or the server configuration says.

## Slices

1. Tests (`test(webservice/iam)`, Refs #2005) in `auth_test.go`:
   - a JWT with no `tenant_id` plus an `X-Tenant-ID` header gives
     `ErrMissingTenantID`;
   - a JWT with no `tenant_id` and a configured `DefaultTenantID` gives
     `ErrMissingTenantID`;
   - an mTLS certificate naming no tenant and a configured
     `DefaultTenantID` gives `ErrMissingTenantID`;
   - the two tests that asserted the header and default fallbacks go.
2. Fix (`fix(webservice/iam)`, Closes #2005):
   - `auth.go`: drop the header read in `authenticateWithJWT` and the
     `DefaultTenantID` fallback in both `authenticateWithJWT` and
     `authenticateWithMTLS`;
   - `types.go`: drop the `TenantIDHeader` constant and the
     `AuthConfig.DefaultTenantID` field, so no caller can set a fallback;
   - tests that leaned on the default tenant name a tenant through the
     principal instead (JWT claim, or `TenantCertField: "o"`); the
     configured-default cases fold into the no-tenant case, since the
     field no longer exists; `types_test.go` drops its `TenantIDHeader`
     assertion.
