# Plan #1931: a posture-unavailable refusal names the tenant and the policy

## Objective

`ErrPostureUnavailable` carries `TenantID` and `Name`, the same fields as
`ErrPosturePolicyInvalid`, and its message names them when `TenantID` is
set. In a build without the `opa` tag every delivered tenant policy is
refused as unavailable; `Service.PosturePolicyErrors()` then lists one line
per tenant that says which tenant it belongs to. Follow-up recorded in
[1691.md](1691.md) ("Under `!opa` the posture refusal does not name the
tenant").

## Slices

1. Tests (failing first):
   - `tenant_posture_noopa_test.go` (`!opa`): `SetPosturePolicies` with
     `tenant-a` and `tenant-b` returns two `*ErrPostureUnavailable` carrying
     each tenant ID; each `PosturePolicyErrors()` line names its tenant and
     still says "opa build tag".
     `TestCompilePosturePolicy_NoOPA_TheEngineIsUnavailable` also checks
     `TenantID == "t"` and `Name == DefaultPosturePolicy`.
   - `service_test.go` (untagged): the message without `TenantID` is
     unchanged; with `TenantID`/`Name` it contains both.
2. Fix:
   - `errors.go`: add the fields; `Error()` reads
     `vpn: posture policy %q of tenant %q unavailable: <cause>` when
     `TenantID` is set, today's text otherwise. `Unwrap` unchanged.
   - `tenant_posture.go`: both returns in `CompilePosturePolicy` set
     `TenantID`/`Name` from the policy.
   - `admission.go`: the four returns in `(*Service).posture` set
     `TenantID`, and `Name` where the policy name is known.

## Out of scope

- `wire.go`, the refusal codes, what a client is sent.
- `pkg/vpn` and `pkg/api/daemon` refusals (`ErrPolicyEngineUnavailable`).
- Folding `pkg/sdn/policy` into an engine; Rego in the datastore.
