# Plan: #1933 MCP auth adapter has no default tenant

## Objective

`QuicBaaSAuthAdapter.CheckPermission` (`pkg/api/mcp/dragondb_auth.go`) refuses
a validated token that names no tenant with a typed `*QuicBaaSAuthError`
(`QuicBaaSAuthErrorMissingTenant`) before the PEP is called. The dormant
`DefaultTenantID` fallback (config field, struct field, `SetDefaultTenantID`)
is removed. docs/SPEC.md:123 and docs/auth/architecture.md row T7 say the
fallback is gone.

## Slices

1. Test commit (`Refs #1933`): in `dragondb_auth_test.go`, the subtest
   "uses default tenant when not in token" becomes "refuses a token with no
   tenant" (allowed false, error code `QuicBaaSAuthErrorMissingTenant`, mock
   PEP saw no `Check` call); the `DefaultTenantID` assertions in
   `TestNewQuicBaaSAuthAdapter` and the `SetDefaultTenantID` subtest go.
2. Fix commit (`Closes #1933`): the refusal in `CheckPermission`, the new
   error code, removal of the default tenant fields and setter, the two doc
   lines.
3. Rework (coordinator ruling, rounds 1 and 2): the tenantless QuicBaaS
   fallback in `createMCPServer`/`createMCPAuthAdapter`/
   `quicbaasServiceWrapper` stays (mTLS-certificate MCP deployments need
   it); a startup Warn says bearer tokens are refused on that path. Test
   `TestQuicBaaSServiceWrapper_TenantlessTokenRefusedBeforePEP` drives the
   legacy wrapper through the adapter: refused with the missing-tenant code,
   no PEP `Check`. Docs row T7 says so.
