# Plan #1979: TPM simulator tests panic on a sub-112-bit HMAC key under fips140=only

## Objective

The FIPS unit-test shard intermittently panics with
`crypto/hmac: use of keys shorter than 112 bits is not allowed in FIPS 140-only mode`
in pkg/api/daemon (TestTPMSimulator_ActivateCredentialRefusesAForeignCredential)
and pkg/vpn/agent (simulator TPM from newSimulatedHostTPM). Find the short key,
pin it in a deterministic test, and make the path use keys of at least 112 bits.

## Reproduce

    T="$(make -s --no-print-directory print-build-tags WITH_FIPS=1)"
    GOFIPS140=latest GODEBUG=fips140=only go test -tags "$T" \
      ./pkg/vpn/agent/ ./pkg/api/daemon/ -run 'Simulator' -count=20

Result: the panic is deterministic, not intermittent (first run, every time).
The HMAC key is zero-length, `crypto/hmac.New(h, {})`:

- pkg/api/daemon, TestTPMSimulator_ActivateCredentialRefusesAForeignCredential:
  `crypto/hmac.New` <- `go-tpm/tpm2.computeHMAC` (sessions.go:500) <-
  `(*policySession).Authorize` (sessions.go:862) <- `cmdSessions` (reflect.go:1106)
  <- `tpm2.ActivateCredential.Execute` <- `go-xkms/pkg/tpm2.(*TPM2).ActivateCredential`
  (attestation.go:594) <- `activateCredential` (tpm_grpc_service.go:1758).
- pkg/vpn/agent, TestXKMSTPM_IDevIDSignerSignsWithTheTPMKey: same panic from
  `go-xkms/pkg/tpm2.(*TPM2).CreateIDevID`, called by newSimulatedHostTPM.

Cause: go-xkms v0.17.0-alpha opens `tpm2.PolicySession(t, SHA256, 16)` with no
salt and no bind (EK PolicySecret session; the DevID admin session likewise)
and never calls PolicyAuthValue, so the session HMAC key is
sessionKey(empty) || authValue(not included) = 0 bytes. No config this repo
passes (EK HierarchyAuth, EK Password) reaches that key: the defect is wholly
inside go-xkms. The fix belongs upstream: salt the session to the EK (as
pkg/vtpm did in #1581) or use PolicySession with tpm2.Salted(...).

## Slices

1. test (this repo): pin the empty-key case with a reproducer, and skip the two
   panicking simulator tests only under fips140=only, naming #1979 and the
   frames above, until go-xkms ships the salted session.
2. upstream (not this lane, no go.mod bump): go-xkms salts the
   ActivateCredential / CreateIDevID policy sessions; then drop the skips.

## Out of scope

- go.mod / go.sum, go-quicbaas or go-tpm version bumps.
- pkg/vtpm (already fixed), .github/workflows.
