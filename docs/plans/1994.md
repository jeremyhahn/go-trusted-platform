# Plan #1994: HA compute pair (SPEC row 90, ROADMAP row 71)

## Objective

The high-availability profile (`configs/platform/templates/high-availability/`)
ships the three control-plane templates (`supermicro/x10/cp1..cp3`) but no
compute nodes. Add the compute pair, `compute1/compute.yaml` and
`compute2/compute.yaml`, copied from `dedicated/supermicro/x10/compute.yaml`.

## Slices

1. `test(quicbaas)`: `TestShippedHATemplates_ComputePair` in
   `pkg/storage/quicbaas/config_ha_templates_test.go` loads both compute
   templates, validates their `quicbaas` section, and asserts the two
   documents differ only in node identity leaves (`hostname`, `address`,
   `ipv4-address`, `serial`) and that hostname, BMC address and TPM serial
   are distinct. Red until the files exist.
2. `feat(configs)`: add both files. Identities follow the cp1..cp3 pattern:
   hostname `compute-01`/`compute-02`, host addresses `.20`/`.21` in the
   block-4 example zones, platform-VRF `10.4.144.20`/`.21`, BMC
   `198.51.100.151`/`.152` (after the cp BMCs `.148..150`), TPM serial
   `sm-compute-01`/`sm-compute-02`. README status lists them.
3. `test(quicbaas)` (Codex P1 on #1999): the pair check keys on full YAML
   paths, not leaf names. Allowed diffs: `.os.hostname`, `.bmc.address`,
   `.tpm.idevid.serial`, `.network.platform-vrf.address` and
   `.network.bonds[0].vlans[0..2].ipv4-address`; every host-address path
   must differ. `TestShippedHATemplates_ComputePairCheck` rejects a
   `.dns.resolver.servers[0].address` or NTP upstream diff and a shared
   host address. The shipped templates already pass, so no fix commit.
