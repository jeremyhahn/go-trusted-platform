# Plan: #966 — no test sleeps

## Objective

No test at any tier sleeps: every sleep becomes a bounded wait on an
observable condition (issue #966 (c)). The Go tiers have no `time.Sleep`
left on main; the remaining sleeps are Playwright `waitForTimeout` calls in
`web/e2e`.

## Slices (in order)

1. e2esmall: the small web/e2e spec files.
2. e2edash: the dashboard spec files.
3. e2edev: the device spec files.
4. iam roles/groups: `web/e2e/iam.spec.ts`, the Roles and Groups tests.
5. iam groups/permissions: `web/e2e/iam.spec.ts`, the Group members and
   Permissions tests.
6. iam apps/policies (this slice): `web/e2e/iam.spec.ts`, the Policies,
   Error States, API Credentials (tokens) and Applications tests. Eleven
   sleeps replaced:
   - navigation waits use `waitForURL` (/iam/policies/new, /iam/apps/new);
   - client-side search filters wait with `toBeHidden()` on a row that is
     filtered out, and on clear rely on the retrying `toBeVisible()`;
   - the fetch-error tests wait up to 5 s for any error indicator;
   - the delete-error test waits for the mocked DELETE response;
   - `isVisible({ timeout })` checks after a removed sleep become
     `waitFor({ state: 'visible', timeout })`.
7. to 9. the remaining web/e2e spec files.

Each slice is test-only. Its gate is the touched spec under
`npx playwright test --project=chromium` (same pass/fail count as main at
worst) and `make web-typecheck`.

## Out of scope

- Application code under `web/src`. If a wait cannot be expressed against
  what the page renders or what the mocks record, the sleep stays and the
  slice report names it.
- Shared helpers at the top of a spec file, since parallel slices edit
  other hunks of the same file.
