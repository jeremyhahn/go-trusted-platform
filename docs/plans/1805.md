# #1805: unit tests for the React provider context and use-services hook

Part of the UI epic #1665.

## Objective

Give `sdk/javascript/src/react/context.tsx` and
`sdk/javascript/src/react/hooks/use-services.ts` unit tests covering every
export, including edge cases and error paths.

## Approach

The SDK has no renderer (no react-dom or testing library), so the tests run
the hooks under a small stand-in for React's dispatcher: `React.useContext`
is spied on to return a provider's value or the context's default (null),
and `React.useMemo` runs its factory and records its dependency list.

## Slices

1. `src/react/context.test.tsx`: tests for `PlatformContext` (default null),
   `PlatformProvider` (given client used as-is; client built from config,
   from no config and from an explicit undefined client; memo dependencies),
   `usePlatformClient` (returns the client; throws outside a provider) and
   `usePlatformClientOptional` (returns the client; null outside a provider
   or with no client).
2. `src/react/hooks/use-services.test.ts`: for each of the 17 hooks, it
   returns the matching client service, gives a stable instance, follows a
   client change, and throws outside a provider or on a null value.
3. `vitest.config.ts`: add `src/**/*.test.tsx` to `include`, so the `.tsx`
   test runs at all.

## Out of scope

- No change to the modules under test, and no Go change.
- The `tsc --noEmit` errors in the quicbaas and attestation service tests
  also occur on main; they are not fixed here.
