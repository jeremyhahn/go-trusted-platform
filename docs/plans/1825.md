# #1825: unit tests for the platform dashboard pages

Objective: every export of the six platform dashboard pages under
`web/src/app/(dashboard)/platform/` has a unit test covering the normal,
edge, error and invalid-input paths. Each module exports only its default
page component, so the tests render the page with a stubbed fetch (the
boundary the browser crosses) and assert what the operator sees.

## Slices (one commit each)

1. `config/page.test.tsx`: tree, sources, redaction badge, payload envelope
   or bare body, load error, snapshot listing failure non-fatal, key filter,
   reload, snapshot capture, rollback and delete (confirm and decline), download.
2. `events/page.test.tsx`: event list, severity badges, empty and error states,
   filters.
3. `health/page.test.tsx`: system info and metrics, missing fields, error state.
4. `logs/page.test.tsx`: wire entries mapped to rows, empty and error states.
5. `metrics/page.test.tsx`: byte and uptime formatting through the cards,
   service metrics, error state.
6. `services/page.test.tsx`: service table, state badges, empty and error states.

## Out of scope

- Changes to the page modules, unless a test exposes a real bug (then a
  separate `fix(web)` commit after the test commit).
- Go code, the SDK, and end-to-end browser tests.
