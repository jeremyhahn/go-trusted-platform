# Plan: #1743 UI device lookup, counts, profiles, activation, attestation

Epic #1665, slice 11. Web UI and JS SDK, plus one Go fix (Codex round 4).

## Objective
Every operation below is reachable from a dashboard page and exercised by a
Playwright test with mocked API responses:
UpdateDevice, FindDeviceBySerial, CountDevices, GetProfile, UpdateProfile,
FindProfileByMACAddress, FindProfileBySerial, FindMatchingProfile,
CountProfiles, ActivateDevice, AttestDevice.

## Slices
1. `test(web)`: `web/e2e/device-lookup.spec.ts` skeleton, one `test.fixme`
   per operation; this plan.
2. SDK: no change. `device-service.ts` on main already has all eleven methods
   and `__tests__/device-service.test.ts` covers their paths and verbs.
3. `feat(web)`: `web/src/app/(dashboard)/devices/lookup/page.tsx`, a hook in
   `web/src/hooks/`, a nav entry; destructive actions (update, activate,
   attest) behind a confirm dialog.
4. `test(web)`: the spec's fixme tests become real tests, with responses from
   `mockDeviceLookupApi` in `web/e2e/fixtures/api-mock.ts`.

5. Codex round 4: `test` then `fix`. ProfileService.Update keeps stored
   TenantID, BMC and WorkloadPCR on omission (the REST wire cannot carry
   them), with `pkg/device` tests; the activation card describes the
   VLAN lookup /device/activate-json performs (no switch change) and drops
   a result whose target changed or whose request failed, with
   `page.test.tsx` vitest tests.

## Out of scope
- BootCertificate and BootDelivery (device-side boot calls).
- Template pages and template SDK methods (slice 12, #1737).
