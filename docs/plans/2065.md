# Plan: #2065 NetworkZone operations in the UI (epic #1665 slice 28)

## Objective

The four `SDNService` NetworkZone operations (Create, Update, Delete, List)
reach the console through the SDK client, not hand-written fetch. The
webservice already serves them under `/api/v1/sdn/zones`
(pkg/webservice/v1/rest/sdn/zones.go `registerZoneRoutes`, in-process SDN
service); the matrix `-` in the REST column was a handler-name mismatch, so
no Go change is needed.

## Slices

1. SDK and page (this slice).
   - `client.sdn.listNetworkZones/createNetworkZone/updateNetworkZone/deleteNetworkZone`
     on the REST zone shape (snake_case, the Go json tags), types exported
     from the SDK root.
   - The zones page calls them; no `fetch(` left in the page.
   - Tests: sdk `sdn-zone-service.test.ts` (URLs, bodies, escaping);
     web `networking/zones/page.test.tsx` (list through the client, server
     error shown, global fetch never called).
   - Matrix rows to `partial`.
2. Gating and flows (next slice, after #2159 useCapabilities/Gated lands).
   - `<Gated op>` around Create Zone, Edit/Override and Delete.
   - Page vitest cases for create, update and delete through the dialogs.
   - test/integration/web/zones.spec.ts on the real-server harness; matrix
     rows to `covered`.

## Out of scope

- Any Go change (pkg/webservice/v1/rest/sdn/, routes.golden,
  pkg/api/daemon/sdn_service.go are edited by open PRs #1955 and #2145).
- web/src/hooks/use-sdn-bridge.ts (#2145), web/e2e/, the sidebar.
- Moving the REST zone shape to protojson.
