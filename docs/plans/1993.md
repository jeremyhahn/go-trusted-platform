# Plan #1993: no synthetic tenant_owner role in issued tokens (SPEC row 114)

## Objective

`TenantUserService.IssueToken` (pkg/platform/service/tenant_user.go) appends a
synthesized `tenant_owner` role to the roles it passes to the token issuer when
`user.IsTenantOwner` is set. Token roles must come from IAM bindings only. The
`is_tenant_owner` claim stays (derived from the stored user record) until #662.

## Slices

1. Test: `TestTenantUserService_IssueToken_WithTenantOwnerRole` and
   `TestTenantUserService_IssueToken_MultipleRoles` expect the issuer to get the
   bound roles only (no `tenant_owner`) while the user stays a tenant owner.
2. Fix: drop the append in `IssueToken`; fix the `token_issuer.go` comment that
   names the synthesized role.

## Out of scope

- Removing the `is_tenant_owner` claim (#662).
- go.mod, go.sum, workflows, any other row.
