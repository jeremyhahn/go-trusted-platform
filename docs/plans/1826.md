# Plan: unit tests for the storage dashboard pages (#1826)

Part of the UI epic #1665. PR #1855.

## Objective

Give each storage dashboard page under `web/src/app/(dashboard)/storage/` a
vitest unit test file, and fix the defects those tests expose: every page
must catch a refused SDK call and show it instead of leaving an unhandled
rejection.

## Slices, in order

1. Backup page: `backup/page.test.tsx`; fix: catch a refused create, delete
   or restore.
2. KV page: `kv/page.test.tsx`; fix: catch a refused put or delete.
3. Objects page: `objects/page.test.tsx`; fix: upload an empty file as
   empty content, catch refusals.
4. Time series page: `timeseries/page.test.tsx`; fix: catch a refused
   aggregation or delete.
5. Vector page: `vector/page.test.tsx`; fix: catch a refused create, delete
   or search.
6. Carry: merge main in (merge commits only), keep `make web-test-unit` and
   `make web-typecheck` green.
7. Bulk delete (Codex P1 on #1855): in each of the five suites, a canceled
   bulk confirmation deletes nothing, and a refused first deletion is
   reported while the next selected item is still deleted, with no
   unhandled rejection.

## Tests

`make web-deps` then `make web-test-unit` runs every suite above;
`make web-typecheck` checks the pages and tests compile.

## Out of scope

- End-to-end (Playwright) specs for the storage pages.
- Changes to the SDK or the storage backend.
- Web lint (not gated, #419).
