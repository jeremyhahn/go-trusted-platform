# Plan: #2044 compute UI coverage (epic #1665 slice 7, ruling 972)

Objective: every ComputeService operation in the #2044 checklist has a web
control that calls the SDK client, with vitest for the hooks/pages and a
real-server Playwright spec, and its coverage-matrix row reads `covered`.

## Slices, in order

1. CreateSnapshot (this slice): the snapshots page Create Snapshot button
   opens a dialog (VM, name, description, include memory) that calls
   `compute.createSnapshot` (POST /vms/{id}/snapshots) and re-reads the list.
   Tests: `compute/snapshots/create-snapshot.test.tsx` (create + re-read,
   refused create as destructive toast with the dialog kept open, no create
   until a name is typed).
2. GetVMMetrics: `useVMMetrics` over `compute.getVMMetrics`, with its
   vitest; wired into the VM detail page once #2148/#1675 release it.
3. AttachDisk / DetachDisk / ResizeDisk controls on the VM detail page over
   the existing SDK methods, after #1946 and #2148 land.
4. SuspendVM, ResumeVM, GetSnapshot, PrepareMigration, FinalizeMigration:
   SDK methods first (compute-service.ts is held by open PRs), then controls.
5. test/integration/web compute snapshot create spec on the real-server
   harness; coverage-matrix line for CreateSnapshot to `covered`.
6. Wrap the create control in `<Gated op="POST /vms/{id}/snapshots">` once
   #2159 (capabilities) lands.

## Out of scope for slice 1

- Go changes (router.go, handlers.go, compute.proto): the server already
  serves CreateSnapshot.
- sdk/javascript changes: `createSnapshot` already exists.
- The held snapshots page.test.tsx, VM detail client, vm-operations and the
  migrations page (open PRs #1675, #2148).
- web/src/hooks/index.ts, docs/ui/coverage-matrix.md, Playwright runs.
